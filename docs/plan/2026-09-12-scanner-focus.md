# 笼卡扫码定位与校正动画

## 实现

- 扫到有效二维码立即停止镜头，查询笼卡；动画不控制查询、重试或继续扫码。
- 根据识别器实际返回的四角，在冻结原图上显示蓝色定位框，停留 140ms，再用 560ms 将二维码放大、旋转及透视校正到窗口中央。
- 校正纹理取自镜头原始像素，不重新生成二维码，不加入模型或新依赖；像素处理仅在识别成功时执行一次，输出 512px。
- 取景窗口保持正方形，完整容纳相机画面，二维码最终占窗口边长的 88%；提示文字放在画面下方。
- 减少动态效果直接显示校正结果。动画中改变偏好或窗口尺寸时收敛到最终画面；继续扫码和离开页面会清理动画与镜头。
- 边角、截图或纹理处理不可用时安全回退，已识别的笼卡仍可查询。

## 扫码详情后续修复

实际公开接口返回 `{ item }`，原查询 hook 将其当成扁平笼卡对象，两处页面因此字段空白并错误回退到“待接收”。动画测试原先使用扁平模拟响应，未覆盖这个真实契约。

- 使用显式 `CageCardDetails` 与 `{ item }` 契约，校验响应后解包；不完整响应显示错误，缺少状态显示“状态未知”，零数量正常呈现。
- 系统内与匿名扫码页同步修正；相同识别码再次查询或扫描时重新读取，镜头运行期间使用最新查询回调。
- `scanner-data.spec.ts` 使用隔离数据库和真实业务 API 验证已打印、待进驻、已预留、已入驻四阶段，以及匿名查询、旧长码和两页四档视口。
- 动画回归的模拟响应改为真实 `{ item }` 结构；新增 hook 契约、异常响应与零值回归。
- 开发数据库仅只读抽查：接口已返回“已接收”及完整批次、负责人、IACUC、品系和房间信息；未修改用户数据。
- 修复后完整检查通过（315 项 Vitest、293 项 Python）；构建、12 项相关浏览器回归及差异检查通过。仍使用上述代码验证副本完成全量门禁。
- 真实链路的四档截图保存在 `tmp/scanner-data-evidence/`，9 份计算样式和真实 API 状态记录保存在其中的 `observations/`；已目检系统内与公开详情页的数据和布局。
