# 多二维码框选验收

## 操作与数据边界

- 同一画面检查完成且只有一个可读二维码时，保留自动冻结、校正和查询。
- 同时识别到多个二维码时冻结原帧、分别框出并编号，点画面或对应按钮后才查询。编号按从上到下、同一行从左到右排列。
- 支持从原冻结帧重新选择、继续扫描；候选选择期间隐藏旧查询区，选完恢复，焦点回到“继续扫码”。
- 相同内容出现在不同位置时保留不同的框。未完整扫描完的单个结果也需要点选，避免过早选中旁边笼卡。
- 不改变公开笼卡 `{ item }` 契约、身份关联、状态计算或数据库结构；测试写入均在隔离数据库。

## 实现归属

| 范围             | 唯一来源                                                               |
| ---------------- | ---------------------------------------------------------------------- |
| 同帧多码提取     | `multiQr.ts`：已解码区域掩蔽、重叠分区、按位置去重                     |
| 后台线程         | `qrScanner.worker.ts`：原图像素转移往返，原始帧不被改写                |
| 镜头、候选与取消 | `useCameraScanner.ts`：单任务在途、停止与离开终止 worker、废弃过期响应 |
| 框选与辅助按钮   | `ScannerCandidates.tsx`，`data-feature="intake"`                       |
| 布局与焦点       | `src/styles/features/intake.css`，沿用 Ant 按钮和语义 Token            |
| 点选后校正       | 现有 `ScannerCapture.tsx`、`frozenQr.ts` 与 `qrGeometry.ts`            |

复用现有 jsQR，没有引入新的识别模型或依赖。每帧计划最多 32 次解码、16 个候选、900ms 工作预算；达到限制会标记未完成，页面仅呈现已读出的候选供手动点选，不声称已找全。单次同步解码只在后台线程执行，终止 worker 可立即取消。

二维码模糊、遮挡、太小或透视过强时仍可能读不到，需要靠近或调整角度。浏览器无法启动后台识别时保留重试和手工查询入口；无法显示冻结帧时仍可用文字按钮选择。

## 验证

- `multiQr.test.ts` 使用真实二维码像素，覆盖单码、左右／上下多码、四码、重复内容不同位置、边缘与透视、预算和取消。
- `useCameraScanner.test.tsx` 验证后台线程、相机、延迟响应、选择前不查询、重新选择及可视化失败回退。
- `scanner-multi.spec.ts` 使用真实相机流与两条不同状态的真实笼卡记录，覆盖点选前零查询、只打开选中记录、同帧重选、四码、五档视口、触屏和键盘。
- 五档截图与 computed style：`tmp/scanner-multi/`；画面框中心与原始帧坐标映射一致，辅助按钮默认 32px，无横向溢出。
- 原有扫码动画、接收／预留／入驻数据、权限失败、匿名新旧链接等 12 项浏览器回归通过。
- 新增多码浏览器回归 3 项通过；打包后的独立隔离服务另通过多码与相机可靠性 6 项回归，验证生产资源中的后台识别器可正常加载。生产构建截图与坐标证据：`tmp/scanner-multi-production/`。
- `npm run check` 通过：344 项前端测试、293 项 Python 测试，以及格式、类型、lint、架构、UI、样式和文档检查；`npm run build` 与 `git diff --check` 通过。
- 全套检查在 `/tmp/cageledger-ui-validation` 同步验证副本执行，排除与本次改动无关的未跟踪著作权申请资料；实际业务数据未用于测试写入。

实体手机镜头对焦、低性能设备和 Safari 尚未实机验证。
