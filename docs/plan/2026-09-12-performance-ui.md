# 性能与统一交互优化任务

状态：已完成。基线：beta / ef2a9c9。负责人：当前目标任务。范围覆盖工作台公共组件及总览、接收、笼位、检疫、巡检、结算、流程、设置入口。

## 目标与边界

提升响应速度和交互可预期性：输入及筛选即时可用、首次加载有结构占位、刷新保留上下文、反馈一致，遵守 Ant 默认 32px／紧凑 24px／强调 40px 控件尺度、语义颜色、单一主操作和既有布局归属。不通过增加等待或遮罩制造流畅感。

保留现有业务规则、权限、原始数据、Word 与打印版式。测试使用隔离库；用户已有软件著作权申请资料不属于本任务。提交、推送、打标签及生产发布另行授权。

## 结果与证据

### 实施结果

- P01：待检疫查询从按每条到货记录相关扫描改为一次来源集合，排除手工来源的空关联；新增空来源、分页、日期及接收状态回归。没有数据库迁移或原始数据改写。
- P02/P03：检疫隐藏面板不发请求；同类列表换页保留结果，详情不使用其他批次占位数据。接收、结算、数量统计表、巡检、流程、报销及日志复用非遮罩刷新提示；检疫列表、来源选择及供应商历史增加重试入口。目录按创建／详情操作启用。
- P04/P05：表格骨架由 88 个块减为 44 个，小屏取消固定 760px 占位宽度。Ant 按钮统一 140ms 反馈与 0.98 按压比例，删除悬浮位移和重复通用按压覆盖；loading／disabled 不缩放，减少动态效果停止骨架循环及位移。
- P06/P07：检疫标题操作使用公共工具栏；收敛报告区间距，小屏及短横屏工具栏随内容滚动；原始图片延迟加载／异步解码。混样表按每轮渲染预建来源索引、分配集合和选项，避免在每个单元格重复全量遍历。

### 性能证据

专用基准使用临时内存库：2,000 条已接收到货记录、300 个检疫批次、1,500 个来源（含 300 个手工来源）；预期待检疫 800 条。每组运行 5 次完整 repository 查询（计数、分页、状态装饰）。复现入口：`node scripts/run_python.mjs scripts/benchmark_quarantine.py`。

| 指标             | ef2a9c9 基线               | 本次实现                           |
| ---------------- | -------------------------- | ---------------------------------- |
| 查询中位耗时     | 918.53ms                   | 3.59ms                             |
| 查询最大耗时     | 1051.88ms                  | 34.90ms                            |
| 查询计划         | CORRELATED SCALAR SUBQUERY | LIST SUBQUERY／CREATE BLOOM FILTER |
| 返回的待检疫总数 | 800                        | 800                                |

接口历史另用两份相同规模临时库，分别运行基线与本次服务；通过管理员接口读取相同 `hours=1` 窗口，采样周期均为 60 秒，每组含 30 次待检疫查询、登录和健康请求。版本均为 1.2.12，未升级版本；基线 checkout 为 ef2a9c9，优化组为本次工作区代码。

| 历史指标               | 基线     | 本次实现 |
