# 多人负责人展示与个人筛选验收

基准：`main` 的 `3c485ab`。本轮不发布、不部署，不修改原始数据库或附件。

## 行为与兼容边界

- 项目负责人、实验负责人按顿号显示，保留人工输入原文与原有审计；同一 IACUC 的人工补充不会因表单再次匹配而被覆盖。
- 个人筛选采用显式 `personFilterMode=individual`，精确成员匹配、列内 OR、跨列 AND；共同负责人记录只计一次。未指定参数的旧接口仍按完整原值匹配。
- 不反写 IACUC 汇总表。导入更新保留在旧来源姓名基础上追加的人员，其他字段沿用原同步、保护与留档规则。
- 原始完整 PI 仍用于减免、身份配置、结算分组与操作目标；不拆账、不合并历史组合，不修改账单快照及财务打印模板。
- 无数据库结构迁移。读取标量姓名的不同值后映射至原存储键，不下载逐日详情、不逐行请求。

## 验证结果

- Python 相关用例 105 项通过；前端相关 Vitest 16 个文件、104 项通过。
- Chromium 相关回归 29 项通过：多人筛选与编辑、重复确认、辅助请求延迟、数量表失败保留、技术服务和单据流程。另有数量表键盘导航 2 项通过。
- 类型、受影响文件 ESLint／Prettier／Ruff、Markdown、架构及 API 清单检查通过。预约表单字段抽出为独立组件，移除已回落的历史规模豁免；原 IntakeView 954 行警告保留。
- 生产备份的独立副本：53 张原表、37,795 条原记录及 4,119 条原审计保留；457 组核算、347 张账单 HTML、347 份 Excel、3 份代表 PDF，与基准相比无差异。副本已有 20 项历史告警保留。
- 副本逐一验证待接收项目负责人 56 人、实验负责人 93 人、数量表项目负责人 99 人，结果 ID 与精确成员预期全部一致。249 条批次、889 张数量表的未缓存个人筛选中位耗时约 0.12／0.63 ms；这是本地 SQL 测量，不代表生产网络耗时。
- 原数据库目录与附件目录共 333 个文件的 SHA-256 前后相同。
