# v1.2.8 后端生产加固验收记录

## 范围与约束

本轮检查 HTTP 输入、认证会话、权限、报销核销、SQLite 生命周期、缓存、日志、上传解析、运行配置和开发代理。保持现有 API、数据库结构、业务口径、权限角色及前端调用兼容；没有引入框架、ORM或数据库迁移。

## 风险与处理

| 优先级 | 风险 | 处理结果 |
| --- | --- | --- |
| P0 | 报销明细 ID 可被其他单据复用 | 服务层批量核验归属，SQL 更新再次限制同一单据 |
| P0 | 并发确认核销时读取余额后再写，可能超额 | 合并为带余额条件的原子更新，并补双线程竞争回归 |
| P0 | 非有限金额进入账务计算 | 写入边界拒绝布尔、`NaN`、`Infinity` 和非法数字 |
| P0 | multipart 简单切分可能破坏二进制正文 | 使用标准 MIME 解析，校验边界、截断和重复字段 |
| P1 | SQLite 连接及测试子进程句柄未及时释放 | 最外层事务退出关闭连接，异常路径也释放资源 |
| P1 | 缓存键拼接碰撞、空结果无法命中、系统时钟回拨 | 确定性 JSON 摘要、显式 miss 标记、单调时钟 TTL |
| P1 | 登录暴力尝试与过期会话累积 | 账户/来源双层窗口限流，登录成功清账户计数，创建会话时清理过期记录 |
| P1 | Cookie 写接口缺少来源约束 | 严格同源校验，跨域只允许显式白名单；开发代理仅开放当前回环端口 |
| P1 | 系统异常可能暴露内部信息且请求难定位 | 客户端返回通用错误与请求 ID，服务端保留脱敏结构化上下文 |

## 数据库与接口结论

- 没有 Schema 或索引变化，因此无需 migration，旧数据库可直接启动。
- 数据库连接仍采用 SQLite 短连接模式；事务提交、回滚、嵌套上下文和提交失败均验证释放。
- 报销核销保持原接口与错误文案，新增的并发保护位于同一事务内。
- JSON 接口继续只接受对象；畸形 UTF-8、非法长度、截断正文、数组/标量和非标准数值返回 400。
- 认证失败仍返回统一文案，达到限制后返回 429 与 `Retry-After`。
- API 日志不记录查询参数、密码、Cookie、请求正文、SQL 或原始用户代理。

## 性能证据

临时库包含 1 万笼位和 10 万条数量记录：深分页 P95 0.18ms，按月房间聚合 4.22ms，20 并发结算候选 P95 14.08ms。缓存修复减少空结果重复查询；本轮没有修改生产运行库，也没有用测试流量污染生产性能历史。

## 保留的技术债务

- 图表组件仍形成约 1.46 MB 的独立未压缩分包，按需加载已存在，但可继续评估更细粒度拆分。
- 架构门禁保留 12 个既有模块体积提醒；当前没有越过阻断阈值，不在安全补丁中做高风险拆分。
- SQLite 适合当前单机部署；若未来改为多实例写入，需要独立评估数据库与分布式限流方案。
- 本地登录限流是单进程内存状态，符合当前单实例部署；多进程部署需改用共享存储。
