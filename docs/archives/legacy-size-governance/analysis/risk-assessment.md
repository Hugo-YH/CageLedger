# legacy.py 尺寸治理：风险评估

## S.U.P.E.R 架构健康度

| 原则       | 状态 | 发现                                                       | 优先级 |
| :--------- | :--- | :--------------------------------------------------------- | :----- |
| S 单一职责 | 🔴   | 兼容入口聚合 schema、业务、文件、HTTP 与路由               | High   |
| U 单向依赖 | 🟡   | 主要路径为 handler → domain/repository，兼容依赖字典仍较多 | Medium |
| P 显式契约 | 🟡   | Router 响应已明确；若干跨层 dict 与回调仍隐式              | Medium |
| E 环境无关 | 🟡   | 配置已集中；兼容入口仍承载运行时组合                       | Low    |
| R 可替换性 | 🔴   | `CageLedgerHandler` 与 legacy helpers 耦合面大             | High   |

**总体结论**：当前属于需要渐进式重构的兼容层。首个 multipart 提取具备独立输入输出和零业务耦合，可作为恢复门禁的安全切片。

## 风险矩阵

| 风险                   | 影响                       | 可能性 | 严重度 | 控制措施                                |
| :--------------------- | :------------------------- | :----- | :----- | :-------------------------------------- |
| multipart 字段解析变化 | 附件、IACUC 与报销上传失败 | Low    | High   | 函数体原样迁移，补纯函数测试与 API 冒烟 |
| 循环导入               | 服务启动失败               | Low    | High   | 新模块只依赖标准库；legacy 单向导入它   |
| HTTP 错误语义变化      | 前端无法显示上传失败原因   | Low    | Medium | 保留 `ValueError` 与 handler 捕获路径   |
| 行数临界回退           | 后续小改再次阻塞检查       | Medium | Medium | 预留至少 25 行缓冲                      |

## 兼容性约束

- 保留 URL、HTTP 状态码、鉴权、上传字段名与错误文本。
- 保留 `server_app.legacy.initialize_schema` 和 `server.py` 的兼容导出。
- 本切片不改变 SQLite schema、缓存、IACUC 或结算口径。
