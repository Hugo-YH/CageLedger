# legacy.py 尺寸治理：任务分解

## 概览

- **总阶段数**：1
- **总任务数**：1
- **预计投入**：S
- **策略**：从边界清晰、零业务依赖的 Web 解析工具开始，保留兼容入口的公开行为。

## S.U.P.E.R 设计约束

- **S**：新模块只负责 multipart 解析。
- **U**：`legacy.py` 单向依赖 `server_app.web.multipart`；新模块不反向导入 handler、domain 或 repository。
- **P**：固定 `parse_multipart_upload(content_type, raw)` 的字典输出与 `ValueError` 错误契约。
- **E**：只使用 Python 标准库，禁止环境、路径和数据库依赖。
- **R**：未来的解析器替换仅修改 `server_app/web/multipart.py`。

## Phase 1：恢复架构门禁

**目标**：把 multipart 解析从兼容聚合层提取到 Web 工具层，令 `legacy.py` 低于 7,100 行硬上限。
