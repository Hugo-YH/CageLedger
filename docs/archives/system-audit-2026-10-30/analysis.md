## 范围与安全基线

React 19 / Ant Design / TanStack Query 与 Virtual / Vite；Python 3.13 标准库 HTTP / SQLite；领域 service 负责事务、校验、审计和缓存，repository 负责 SQL。现有主入口与业务模型保持不变。

原生产离线拷贝仅作只读输入；复制前确认无运行占用且 WAL 为空，完整文件树指纹在复制前后相同。仅在仓库外私有目录运行一致性备份、迁移、HTTP、浏览器、恢复和故障测试。账单金额、源版本、关联、权限、原审计正文和附件字节按既有副本核查与恢复契约验收。仓库报告只写脱敏聚合，不保存真实行值、身份、附件或私有日志。

## 架构与风险判断

沿用现有分层和 ports，不增加跨层写入或全局共享业务状态。高风险点是导入覆盖、账务快照、测试工具自证；先以合成反例验证，再以隔离真实副本检查。布局重设计、通用会计冲销模型、统一请求幂等协议和历史数据清理不属于本批无歧义修复。

公开方案对标由监督线程提供官方来源后整合；未取得来源前不将主观经验写作外部事实。JCMS仅参考领域模型，不参考其停止支持的技术栈。

## 已核实的实际调用链

- 在线：系统设置→数据管理→`DataView.upload`→`/api/reimbursement-records/import-monthly` / `import-arrears`→管理员校验→领域导入。B1修复此输入边界，原计算→登记、归档与账单快照不变。
- 在线：工作区桌面/移动导航→主页/刷新；系统功能、技术服务、检疫等已声明guard的表单复用离开保护。数据管理上传另增加busy保护。
- 暂缓：`ReconciliationPanel` 仅由兼容barrel重导出，当前路由无调用。其首20项与错误反馈候选不作为主要在线缺陷，也未借此改写财务流程。
