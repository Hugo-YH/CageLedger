# 备份恢复演练契约

`npm run verify:restore` 将显式提供的离线数据库与同批附件复制为带清单的备份包，再恢复到另一个隔离目录，使用当前代码验证恢复结果。它是手动执行的自动化演练工具，不登记定时任务，也不切换生产环境。

```bash
npm run verify:restore -- \
  --database /absolute/offline-backup/database/cageledger.sqlite \
  --files /absolute/offline-backup/files \
  --output /absolute/new-private-restore-drill
```

`--pdf-samples` 默认为 `3`，指定 `all` 才检查全部账单PDF。`--timeout` 默认为900秒，分别限制每份独立数据库的应用核验进程。

## 输入与隔离

- 输入必须是停止写入后的同批完整备份或一致性快照；不得指向正在使用的生产数据。工具拒绝非空WAL／journal，不自动执行checkpoint，不忽略未合并写入。
- `--files` 指向备份的完整 `data/files/`，即使确实没有附件也必须显式提供空目录。仅有SQLite无法证明附件完整。
- 原数据库、伴随文件及附件只读；运行前后核对大小及SHA-256。数据库使用immutable连接读取，不触发原库迁移。
- 输入、目录内容和输出路径拒绝符号链接，附件拒绝特殊文件与越界路径。输出必须在仓库外且尚不存在，与原库、原附件不能重叠，不覆盖旧证据。
- 私有目录0700，复制文件和报告0600。备份包及恢复目录均独立复制，不使用硬链接，不删除未引用文件，不覆盖源目录。
- 记录实际Python／SQLite／Node与关键安装依赖版本，依赖清单及运行时输入纳入代码变化检查。恢复与对照共用当前安装依赖，不证明旧版独立依赖环境或容器位级重建一致。
- 每份应用副本使用独立子进程、数据库、附件、索引、日志、PDF缓存。清除远端凭据，禁用更新检查、自动导入和性能后台记录；不运行应用启动后台线程。Python网络仅允许回环连接，不查询远端反馈、发邮件或重放同步任务。
- HTTP绑定回环随机端口，临时账号和会话仅存在于副本；结束关闭HTTP服务，超时终止本次进程组。代码指纹包含应用、共用核查工具和恢复工具，期间变化则结果无效。

## 演练步骤与覆盖

1. 检查SQLite完整性、外键和所有原表记录身份，生成原数据库及完整附件树清单，包括空目录、未引用的历史文件和各版Word。
2. 生成 `bundle/database/cageledger.sqlite`、`bundle/files/` 和 `bundle/manifest.json`，逐文件核对字节与SHA-256；再仅从该包恢复到 `restored/runtime/`，重新核对全部内容。
3. 另用SQLite备份API生成 `control/` 数据库对照。两份数据库运行相同的当前代码，复用[数据库副本核查](database-copy-review.md)中的必需阶段：原字段投影、全部原审计全文、所有历史账单及完整行、全部HTML／Excel、明确样本数的PDF、实际源表重新核算、真实HTTP及原应收GET同步、历史问题分类。对照和恢复结果必须一致。
4. 在初始化前从数据库提取报销、流程、巡检照片、检疫原始附件／预览／报告、反馈本地文件，以及全部巡检目录版本的参考图引用。缺失、大小不同或已有SHA-256不同分别列出；不会把启动时补齐的种子图片冒充原备份文件。
5. 在实际恢复目录启动现有HTTP下载接口，逐个核对可访问的本地附件与清单字节；历史Word按现有接口转换PDF并检查可解析页。隐藏／已移除的文件只核对存储，不绕过现行可见性规则。下载后核对所有数据库记录、审计和原附件未被改写。
6. Gitea来源的附件保留远端标识、任务及已有本地缓存，单独列为远端未验证。其下载规则仍依赖原Gitea配置，缓存存在也不代表脱网可用。演练不改变同步语义。

升级迁移、历史问题自动留档及应收GET同步均只发生在独立副本，并按现行规则验证，不修复或清理原业务记录。

## 结果与限制

输出包括 `report.md`、`report.json`、备份清单、恢复及对照数据库、阶段结果和日志。均可能包含业务信息，应保存在私有位置，不提交Git。

- 退出0：`passed` 或 `passed_with_warnings`。后者仍有既有业务问题或远端附件依赖，不表示生产备份完全没有异常或全部附件均可脱网恢复。
- 退出1：`failed`、`incomplete`、`input_changed` 或 `code_changed`。缺失附件、内容不一致、HTTP失败、两库业务差异、超时、未完成或核验期间输入／代码变化均不能通过；失败证据保留。
- 退出2：无效输入、路径或参数，拒绝覆盖已有目录。

工具不备份部署环境变量、Compose、运行日志及数据库外导出的结算文件；这些仍须按[备份与维护](../../wiki/备份与维护.md)单独备份。不验证外部Gitea／AI、生产切换、浏览器像素版式，也不能证明备份之后实际新增的数据完整。PDF文本和页数检查不替代发布前的打印验收。

这不是生产恢复命令。演练成功不授权覆盖生产数据库、附件、提交、推送或发布。
