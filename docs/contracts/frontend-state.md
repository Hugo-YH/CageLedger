# CageLedger 前端状态契约

页面是否现役先按 [当前实现与兼容边界](current-baseline.md) 核对。目录、typed hook 和兼容 re-export 的存在不等于有当前 UI 调用；未接入的历史业务组件由 `frontend-lifecycle.json` 明确登记，旧组件测试保留但不作为当前页面覆盖。

本契约约束 React 前端的状态归属、查询缓存和持久化。当前实现以 TanStack Query、页面局部状态和 `UiProvider` 为核心。

页面布局、工具提示、弹窗、异步反馈和可访问性交互规则见 [UI 交互系统](ui-interaction-system.md)。

## 状态分类

| 类型           | Owner                   | 示例                                           | 生命周期                        |
| -------------- | ----------------------- | ---------------------------------------------- | ------------------------------- |
| 会话状态       | TanStack Query          | 当前用户、角色、房间授权                       | Cookie Session 有效期           |
| 服务端状态     | TanStack Query          | bootstrap、笼卡、笼位、统计表、流程、台账      | staleTime 与精确失效控制        |
| 工作区 UI 状态 | `UiProvider`            | activeView、sidebarCollapsed、settingsExpanded | 当前页面会话                    |
| 持久 UI 偏好   | `uiStorage.ts`          | activeView                                     | localStorage `cageledger.ui.v2` |
| 页面草稿       | feature component       | 表单值、当前分页、筛选、弹窗、选中项           | 页面挂载期间                    |
| 高频录入状态   | 页面局部 state/ref      | 数量统计表单元格、焦点、当前行                 | 输入控件生命周期                |
| 派生状态       | `useMemo` / pure helper | 汇总数、筛选结果、结算展示值                   | 由源状态重算                    |

结算管理和单据跟踪的已应用筛选、排序、页码、页大小、表格密度与滚动位置由 `WorkspaceMemoryProvider` 在当前账号工作区会话内保留。已保存数量统计表按相同会话边界保留筛选、排序、页码、页大小和滚动位置。跨业务页返回恢复这些 UI 状态；退出、切换账号或刷新页面后重置。草稿、弹窗、选择与 API 业务对象不进入此缓存。翻页、排序保留当前页面实例中的选择，应用筛选仍通过 `useSelectionScope` 清空选择。

数量统计表录入页通过 `useWorkspaceMemory` 保留最小保存回执，仅包含标识、IACUC、月份、房间和成功时间，供工具栏下方核对。回执只由当前有效的录入保存成功响应更新，业务字段取服务端返回值；继续填写、新建、保存失败和已保存列表编辑不替换回执。它沿用当前账号会话边界，不缓存完整 API 业务对象，不恢复表单草稿，也不替代 Query 缓存或保存成功通知。

服务端业务对象不写入 localStorage。旧键 `cageledger.v1` 和 `lahcas.v1` 在 UI 存储迁移时清理。

## QueryClient 默认策略

配置位于 `src/react/api/queryClient.ts`：

| 配置                   | 当前值            | 目的                                                |
| ---------------------- | ----------------- | --------------------------------------------------- |
| `staleTime`            | 15 秒             | 合并短时间重复读取                                  |
| `gcTime`               | 5 分钟            | 保留近期页面缓存                                    |
| query retry            | 瞬时错误最多 1 次 | 吸收网络失败、408、429 和 5xx；权限、参数错误不重试 |
| mutation retry         | 0 次              | 避免写入重复执行                                    |
| `refetchOnWindowFocus` | `false`           | 保持高频工作台输入稳定                              |

只读查询将 TanStack Query 的 `signal` 传给请求层。查询键变更或最后一个使用者卸载时，取消不再需要的请求；仍有其他使用者的共享请求继续执行。取消不自动重试，响应体读取中断也不能被当成成功的空数据。

运营总览保持15秒的客户端过期策略，使用条件GET重新验证。每个月份的完整响应和ETag共同归属对应Query；304复用该Query的已有数据，200更新数据与ETag，错误或取消维持原失败语义。服务器未返回ETag时沿用普通JSON读取。登出清理Query时同步移除验证标识，不额外持久化业务数据；接收批次的保存、删除、确认接收及打印登记同步失效总览根键。

总览请求状态条与稳定数据图表隔离，数据引用不变时不因后台读取开始/结束更新图表；数据、主题或房间选择变化仍正常更新。首次成功空态只显示原占位，首次有可绘数据才创建该图表；已创建实例在后续空/非空转换间保留。真实零值、无记录、筛选无趋势与读取失败保持不同提示，不改变原viewport加载门槛或月份失败保留旧数据的行为。

IACUC 搜索先去除首尾空白并转大写，再做 250ms 防抖；查询键保留结果条数。输入变化和清空时立即隐藏旧候选项，避免误选。失焦时需要立即匹配的表单复用相同查询缓存，回填前检查请求是否仍有效；新输入、新建草稿、关闭表单和卸载都会使旧回填失效。

## 查询键

查询键集中在 `src/react/api/queryKeys.ts`。

| 根键                    | 数据                                 |
| ----------------------- | ------------------------------------ |
| `session`               | 当前会话                             |
| `public-cage-card`      | 公开扫码与工作区笼卡查询共享结果     |
| `bootstrap`             | summary、room、full 基础设施         |
| `intake`                | 待接收批次和筛选项                   |
| `quantity-sheets`       | 数量统计表列表、详情和筛选项         |
| `billing-workflows`     | 结算流程                             |
| `reimbursement-records` | 报销台账列表与详情                   |
| `reimbursement-ledger`  | 结算应收、报销单、核销分摊和历史迁入 |
| `users`                 | 账号                                 |
| `researchers`           | 独立实验人员目录、检索列表及按ID详情 |
| `principal-identities`  | PI 身份与减免配置                    |
| `iacuc-index`           | IACUC 数据和状态                     |
| `audit-events`          | 操作日志分页                         |
| `data-quality`          | 管理员核查留档、当次问题和只读证据   |
| `system`                | 系统信息、管理员运行状态和更新检查   |

查询键参数包含服务端筛选、排序、分页和 actor scope。对象参数保持可序列化与稳定。

系统功能入口开关使用 `queryKeys.systemFeatures`（`["system","features"]`），通过 typed hooks 读取；会话组合响应可初始化不存在的配置缓存，缺少配置时仍独立请求且在成功前不显示业务入口。管理员保存时取消旧读取并更新配置与会话中的配置，避免旧会话覆盖新开关；登录、退出及账号切换清理其他账号的缓存，保存成功同时失效 `audit-events`。全局配置不写入localStorage。活动窗口每15秒同步，切回窗口和重连按Query策略重读；重复读取共享同一缓存，失败保留已加载配置及未保存草稿。

工作区视图身份、持久化合法值及所属模块统一由 `state/workspaceViews.ts` 登记。初始配置加载完成后，已隐藏的上次页面回到总览；后续配置更新只隐藏入口，不强制卸载已打开页面或丢弃业务草稿。新跳转检查目标入口，桌面、手机底栏/更多和跨模块快捷操作共用同一判定。总览保留数量和历史统计，隐藏模块的待办卡改为静态摘要。系统设置和帮助入口始终保留，系统功能页仅管理员可进入。

## 加载边界

列表主查询、共享目录和操作详情使用独立加载边界。待接收和账号列表不等待房间目录；辅助信息失败只禁用依赖它的操作并提供局部重试，不能用空数组或零金额冒充已加载。刷新失败保留已显示列表及草稿，旧范围结果不能执行新范围写入。

共享列表保留逻辑 `useRetainedListData` 只记录上次成功的查询键并观察对应 Query 缓存，不复制或持久化业务对象；复用原查询键对应的查询函数，不因保留旧结果发起额外读取。首屏无数据失败时显示错误与重试，不以空表或零值冒充成功；分页、排序或刷新失败时可显示上次成功结果及其实际页码，明确提示并禁用依赖旧结果的选择、行写入、打印和导出，独立筛选、新建与重试保持可用。重试成功后恢复操作，已打开的草稿不因列表刷新而被覆盖。

保留范围必须包含资源的硬业务边界：数据核查按留档 ID，检疫列表按路径及方法，供应商明细按筛选和供应商、方法、初检或复检分组隔离；变更边界时不展示旧范围的占位数据。账号 ID、角色或授权房间变化时立即屏蔽旧结果，重置对应资源查询并等待新范围成功读取，退出登录清除业务查询。查询缓存仍按原授权校验，前端屏蔽不替代服务端权限检查。

授权房间目录通过 `room-directory` 查询共享，设施结构、单房间工作数据和笼架笼位归属 `infrastructure`；查询键包含账号ID、角色和排序后的授权房间集合，沿用15秒 staleTime、5分钟gcTime和取消信号。登出清理业务缓存，设施保存与删除同时失效新查询、旧bootstrap及数量表房间目录，不建立独立持久化缓存。

已保存数量表和技术服务列表使用独立摘要类型；选择或删除不能把摘要当作完整明细。数量表仅录入或打开编辑时启用房间及负责人配置，编辑详情和配置并行读取；配置失败保留草稿且禁止保存。技术服务预览、编辑点击后才读取详情，编辑固定本次加载的明细快照，避免后台刷新覆盖草稿。

待接收批次列表和跨页选择使用 `IntakeBatchListItem` 摘要，不能作为完整批次保存。编辑时按 ID 读取完整详情，关闭弹窗、改变模式或切换目标使迟到结果失效；失败时保留加载边界并支持重试。列表打印在用户手势中预开窗口，冻结选择及其 `updatedAt`，按需分批获取完整记录并检查版本；任一读取失败或版本冲突不打印。统计使用真实摘要字段，不推测缺失值。

巡检和异常列表使用明确摘要类型；巡检详情、附件与事件在打开详情时读取。异常处置使用摘要中的真实操作字段，不将摘要写成完整记录。数据核查的留档目录与最新问题分别请求；初次返回后固定留档 ID，分页、筛选及重试不跟随新留档切换，空留档显示明确空状态。

检疫供应商历史只在展开时请求分组明细；检测/报告在同路径同方法下保留旧页，方法或列表类型改变时不串数据。目录只在新建检测时读取，过期缓存的重取必须成功后才创建编辑器，失败可重试或取消。巡检标准页读取轻量草稿状态，进入编辑才读取完整草稿；反馈构建信息仅在创建抽屉开启时读取。

| 页面       | 初始查询                   | 按需查询                                   |
| ---------- | -------------------------- | ------------------------------------------ |
| 主页       | `bootstrap(summary)`       | 无                                         |
| 笼卡管理   | intake 当前页              | 筛选项、批次编辑详情                       |
| 笼位管理   | `bootstrap(summary)`       | 当前房间 `bootstrap(room)`                 |
| 饲养费管理 | 数量统计表当前页、房间列表 | 单表详情、IACUC、PI 结算                   |
| 单据跟踪   | 结算流程当前页             | 流程详情（版本、事件）与留档附件           |
| 系统设置   | 对应页面的独立查询         | 管理员运行状态、更新检查、筛选项和上传结果 |
| 公开扫码   | public cage-card endpoint  | 无登录会话依赖                             |

“关于系统”的运行状态查询只在管理员进入页面时启用，采用手动刷新，不做高频自动轮询。性能快照属于当前服务进程，重启后重新累计；普通账号只读取公共系统信息，不请求管理员运行环境接口。

业务页面通过 `React.lazy` 加载，首页无需等待笼卡、结算和系统设置代码块。

更新公告先用同一更新日志生成链产出的轻量版本索引及当前账号已读历史判断未读；确认有未读版本才加载正文模块。入口和弹窗共享账号范围内的历史查询，退出或换账号后的迟到确认不能回填新账号缓存。版本顺序、新账号仅显示当前版本及批量确认规则沿用既有行为。

## 写入和失效规则

| 写入                       | 必须失效或更新的查询                                                            |
| -------------------------- | ------------------------------------------------------------------------------- |
| 登录                       | 清理其他账号查询并写入 `session`                                                |
| 登出                       | 清除 session 之外全部查询，写入空会话                                           |
| 保存/删除/确认接收批次     | `intake`、`quarantine`、`dashboard-overview` 根键；涉及入驻时同步房间 bootstrap |
| 保存占用、预留、正式入驻   | 当前 `bootstrap/room/{roomId}`                                                  |
| 保存/删除数量统计表        | `quantity-sheets`、结算候选及 `dashboard-overview` 根键                         |
| 生成结算单或发起流程       | 数量统计表、流程、报销台账相关根键                                              |
| 更新/删除报销台账          | `reimbursement-records` 根键和当前详情                                          |
| 保存报销单、附件或核销分摊 | `reimbursement-ledger` 根键和受影响报销单详情                                   |
| 保存房间、笼架、笼位       | `bootstrap` 根键、设施查询和数量统计表房间列表                                  |
| 上传 IACUC                 | IACUC 状态、完整索引、PI 配置和受影响业务列表                                   |
| 保存账号                   | `users`                                                                         |

失效范围与服务端写入范围一致。高频输入期间不触发列表根键失效。

结算流程推进完成后等待关联查询刷新，页面不再额外重复 refetch。批量锁定保留逐条提交顺序，由 `useBatchAdvanceWorkflow` 在整批结束后统一失效流程、候选结算和报销记录查询；不在每条写入后刷新。批量操作同步防重入，失败逐条汇总，页面卸载不会取消已启动的写入，结束后仍同步查询缓存。

“全选当前筛选结果”先读取首个 100 条分页，后续每批最多并行读取 3 页，结果保持分页顺序；失败或取消不继续启动下一批。这只调整只读分页请求，批量发起、撤回及锁定的写入顺序保持不变。关联查询失效仅重新请求活跃查询，非活跃缓存仍需标记过期，不能为减少请求而保留旧状态。

负责人字段使用共享 `PersonNamesInput` 与 `formatPersonNames`：界面顿号展示与原始业务值分离，失焦只改变显示，不触发规范化写入。新列表 hook 和全选读取启用 `personFilterMode=individual`，列表 Query 键与保留旧页的观察键使用同一模式；姓名候选仍按需读取，不阻塞主列表。原始 `pi` 继续用于结算、减免与操作目标，禁止用拆分后的单人名替换对象或重建业务 ID。

## 表单与焦点规则

预约识别的浏览器图片字节只保留在页面局部草稿，不进入 Query、localStorage、批次 payload 或审计；服务端短期暂存，保存成功才独立归档。文字与最多4张图片可共同识别，界面按“饲养需求”和“采购信息”展示结构化来源，表单只使用后端合并后的 `item`，不把许可总量转成本批数量。AI 提取来源事实，规格由服务端规范化；采购数量按明细加明确属于当前明细的额外赠送计算，本次到货备注用于校验，后续到货及需求总数不计入当前到货。依据区保留来源原文、数量事实及服务端计算结果，不确定时提示人工核对。识别与 FileReader 生命周期独立：并发添加不会丢弃前一批读取，读取期间不能保存；修改文字/图片、切页、新建、关闭或卸载会作废旧识别及其 IACUC 回填。失败保留当前文字、图片和草稿。保存/打印/重复确认固定使用发起时的图片与草稿版本，旧保存响应不能清空新草稿。保存成功后清空新图片；已留档图片只读展示，旧编辑请求省略识别依据时继续保留已有留档。

数量统计表和接收批次的通用全选分页也采用最多3路并发。遇到非末尾短页时丢弃其后预取结果，按实际返回条数串行续读；总数变化沿用已处理页的最新total，空页保持停止语义，不漏读服务端实际分页上限较小的记录。

数量统计表全选分页使用 `view=ids`，只取标识，沿用原筛选、排序、取消和选择范围；数组保持操作顺序，memo Set 仅加速当前页勾选判断。关闭动物数量时只卸载对应输入控件，行草稿和保存引用继续保留，切回恢复值；按只/天计费仍强制开启动物明细，不能通过虚拟卸载行改变保存内容。

异步PDF导出首轮500ms查询状态；无进展时逐步延长至1000ms、2000ms，状态或已完成份数变化后恢复500ms。最多2秒再次检查，不改变任务失败/重试、切页后继续执行及完成后自动下载的行为。

数量表或 PI 的连续保存可合并尚在等待、且未被用户导出引用的后台 PDF 预热，只占用一个等待槽位并使用最新输入。已启动的渲染不强制中止；过期等待任务在渲染前失败，仍保留发布文件时的版本保护。显式导出不改绑其他版本，冻结账单、授权、队列上限及用户任务优先规则保持。

- 输入事件更新当前控件所属的局部草稿。
- `Tab`、`Enter` 和日期选择保持焦点顺序稳定。
- 保存前校验在局部草稿上执行，失败时定位到首个问题控件。
- 保存成功后再失效服务端查询，并根据返回对象保持当前选择。
- 弹窗关闭回调按现有时机更新目标和业务状态；`Modal` 与常驻 `ModalPresence` 仅在 Ant 退场期间保留局部展示树，`afterClose` 后清理草稿和临时预览资源，不写入 Query 或持久化存储。退出内容不接受交互，`useLatestRequest` 与未保存导航守卫通过 `DialogActivityContext` 立即失效，不能让已关闭表单的异步回调影响下一张表单。
- 同一页面跨响应式断点时保留表单实例和未保存草稿；不通过切换整个外层组件类型来实现桌面/手机布局。
- 异步结果只更新仍然有效的页面实例；查询键变化负责隔离旧请求。

反馈创建从表单校验开始显示忙碌状态并阻止重复提交与关闭。关闭或卸载后完成的校验不得启动写入；已经启动的写入和附件上传继续按原流程完成，但迟到结果不打开下一张详情抽屉。未知提交结果继续保留同一请求标识和内容重试，明确的参数错误才恢复编辑。

## 持久化规则

- `persistWorkspaceView()` 只写当前工作区。
- “清理本地缓存并刷新”调用 `clearUiStorage()` 后刷新页面。
- 会话由 HttpOnly Cookie 管理。
- 业务草稿默认不跨刷新持久化；需要草稿恢复时建立独立、带版本的存储契约。

已保存技术服务明细的分页、页大小、排序、筛选及密度通过账号会话内的 `WorkspaceMemory` 保留；滚动恢复使用活动视图键 `technical-service-saved`。离开再返回恢复列表上下文，退出或切换账号清除这些状态，不持久化表单草稿。筛选摘要可将设施和状态值显示为中文，但删除标签和清空仍使用原始筛选键值，不改变接口参数。

## 新状态评审

预约草稿的可选 `husbandryMonths` 保存已识别的自然月意图，仍属于当前批次本地草稿和服务端批次数据，不另建缓存。缺接收日期时保留月数且天数、结束日期为空；填写或修改接收日期时按自然月重算。手动编辑或清空天数/结束日期时写入 `husbandryMonths:null`，后续日期改动沿用原天数联动。新识别结果未返回月数时清除旧草稿月数，不让上一次识别意图污染新结果。

新增状态前依次判断：

1. 数据是否来自服务端。服务端数据进入 Query cache。
2. 数据是否只属于一个页面。页面局部 state 管理。
3. 数据是否跨多个页面共享。优先通过查询键或明确 Context 共享。
4. 数据是否需要跨刷新保留。仅界面偏好进入带版本 localStorage。
5. 数据是否可以由现有状态推导。使用 pure helper 或 memo 计算。

## 验证要求

- Query key 变化能隔离不同分页和筛选。
- 写入后相关列表、详情和摘要及时更新。
- 高频录入不会因 Query 失效导致失焦。
- 登出后业务查询缓存清空。
- 清理缓存后只清除 UI 偏好，服务端业务数据保持完整。
- React Hooks、查询失效和高频录入改动通过 ESLint、Vitest 和 Playwright 验证。
- 弹窗和异步状态保留键盘焦点、live region 和可访问名称。

## 后端资源繁忙与导出失效

服务器过载或PDF排队达到上限时沿用ApiError和现有局部错误边界展示503，不清空草稿，不自动重试写入。后台预热失败不影响已成功保存的明细；显式导出可由用户重试。旧PDF任务在源数据失效后返回failed及重新导出提示，不能把另一次生成的文件绑定到原任务。前端仍以原始业务ID、版本和账单快照为准，不新增权限推导或金额补算。

声明 `useUnsavedChanges` 离开保护的页面，其主页、刷新、页间跳转与退出复用同一确认逻辑。保存或上传进行中阻止这些应用内离开动作；数据管理上传也注册该保护。取消离开保留草稿、工作区和主题偏好；确认文档跳转只放行紧接着的一次 `beforeunload`，避免重复提示，后续原生离开仍受保护。确认期间重复点击文档操作不重复执行。此规则不把所有会话内草稿缓存改成持久化，也不改变未注册保护页面的现有导航策略。

## 接收预约提交生命周期

录入页与列表编辑共享局部编辑器，普通保存、打印前保存和重复确认复用同一提交入口。提交意图固定业务对象、草稿版本及来源图片快照；重复确认继续使用该意图，不能在失败后重新读取当前图片替换原请求。关闭、换页、新建或修改草稿后，迟到响应不得清空或覆盖新输入；已经完成的写入继续由原Query失效同步。

打印窗口在用户点击时同步打开，保存成功后才交给原打印模块，重复确认后同样遵守。保存失败、版本过期或已失效的意图关闭准备窗口，不标记已打印。列表的跨页选择、失败保留旧页、按需详情和统计/汇总继续使用原查询及业务口径。

新图片识别返回可选 `recognition.review`（version 1、字段对照与核对事项），当前展示直接使用结构化结果，不从中文提示推断类型；历史记录缺少该字段时仍使用原兼容展示，原始warnings和来源事实保留。

预约原始File及上传凭据按稳定、冻结的图片对象用WeakMap关联，不另建强引用图片缓存。识别、保存和重复确认复用上传；新增图片增量上传。账号/角色变化作废上传世代并取消在途请求，旧完成结果不能回填；仅明确410/INTAKE_UPLOAD_EXPIRED在确认未调用模型/未写业务后最多重传一次。品系标准化与共享IACUC查询并行，同输入在途本地识别合并；合并预览取消自己的请求，不取消共享Query，也不取消已启动保存。
