# 代理指令维护

本契约用于维护 `AGENTS.md`、项目 Skills 和开发约定，普通代码修改无需读取。目标是让代理完成用户请求，同时保留业务、数据、验证和发布边界。

## 文件职责

- `AGENTS.md` 保留全项目适用的业务约束、执行边界、完成标准和文档入口。模型选择由调用端设置，仓库不锁定推理档位或模型，也不修改个人配置。
- `docs/contracts/` 维护按领域生效的规则；验证矩阵只在 `testing-strategy.md` 维护。CONTRIBUTING 和 Wiki 提供入口，避免复制多套要求。
- `.agents/skills/*/SKILL.md` 描述能力、准确触发条件和必需边界。较长的示例、参数表按主题放入 `references/`，入口说明何时读取。
- `.agents/skills/*/agents/openai.yaml` 维护展示信息及调用策略。保留原有自动/显式调用意图，不因精简指令批量禁用技能。
- `docs/archives/` 保存已完成工作，不作为活动任务、遥测表或每次会话的必读资料。只有追溯历史时才读取。

## 维护判断

新增规则前，明确它避免哪个已证实的问题、适用于哪种任务、是否已经由代码或契约覆盖。技能名称或一般关键词不足以触发整个工作流。普通修复不默认创建阶段计划、全仓审计、额外审批或指定其他模型执行。

完成标准写用户能观察到的结果及相关验证，不规定所有任务必须经过相同步骤。实现请求包含修复本次引起的失败；仅审查请求保持只读。已有授权足够时继续工作，业务规则变化或未授权外部操作才需要用户决策。

设计参考中的风格、曲线、库与输出模板服从项目契约。审查结论基于影响和证据，不默认否决，也不强制发现数量。纯文本变更不用业务测试证明措辞；提交和发布的完整门禁保持不变。

## 任务提示与完成边界

需要交接的任务可写清目标、范围、必要约束、验收和停止条件；只有确有帮助时才形成计划文件。例如 UI 修复应说明需要解决的可见问题和目标入口，而不是规定先读多少文件、调用多少技能或必须发现多少问题。

小修正直接定位并完成相关验证。全系统审查需要覆盖实际页面和典型状态，不能把 CLI 无告警、空数据截图或首版实现当成最终验收。用户在执行中补充需求时保留原目标与已完成工作，记录真实剩余项。

继续执行的授权应说明具体安全范围，例如运行框架创建的隔离测试、修复本次导致的失败并验证。不要把“本地”泛化为数据可丢弃，也不要把用户已经授权的常规工作改成逐步审批。

## 官方依据

依据 [OpenAI：Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)：技能描述明确适用任务，参考按需读取，任务明确结果与完成边界。保留影响业务正确性、数据与发布的约束，不把既有经验泛化为每次必走流程。

下面的场景用于核对触发与完成边界；真实效果需结合实际任务验证，不能由字数减少或静态检查推断。[历次整理记录](../archives/agent-instructions/2026-09-12-astra-audit.md) 仅在追溯时读取。

## 检查场景

| 请求              | 预期范围与完成行为                                                      |
| ----------------- | ----------------------------------------------------------------------- |
| 修正 Wiki 错字    | 检查目标文档与构建，不加载 UI 或迁移技能；提交前仍跑完整门禁            |
| 修复表单控件高度  | 定位唯一样式来源，按 UI 契约完成四档视口与 computed style 验收          |
| 修改巡检草稿保存  | 读取当前目录模块，验证管理员权限与乐观锁，不更新归档 P0 计划            |
| 审计动画          | 报告证据和未验证假设，不自动改源码或强制凑出问题                        |
| 修复指定动画      | 完成实现和必要验收，不因审计技能要求停在方案阶段                        |
| 修改结算 PDF 汇总 | 同时核对两条渲染链路、跨页结果与前后端回归                              |
| 清理项目指令      | 只改项目指令与引用，不改模型配置、运行库，不触发发布                    |
| 全系统 UI 审查    | 覆盖实际入口和典型状态，修复与验收完成后交付，不停在首个页面或 CLI 结果 |
| 修改后继续实现    | 当前实现与计划位置不符时核对代码，常规差异自主调整，不因旧模板自动停工  |

这些场景用于人工检查触发条件与边界；不能用文案匹配测试替代真实任务表现。若实际使用仍出现无关技能加载或提前停工，针对具体触发点修正，避免叠加更多全局规则。
