# 数据库副本兼容核查

`npm run verify:database` 用于在升级或内部整理后，对比一个明确的 Git 基准和当前工作区。它不连接生产服务，不向输入库写入；实际初始化、HTTP查询、原有应收读取同步、计算和导出均发生在新建副本中。

## 使用

```bash
npm run verify:database -- \
  --database /absolute/path/offline-backup.sqlite \
  --baseline-ref HEAD \
  --output /absolute/path/new-private-review
```

基准必须是本地可解析的 Git 提交或 tag；开始时固定为提交SHA。基准代码必须支持输入备份格式，并具备本工具调用的审计、快照和诊断入口；较早版本缺少这些入口或不能加载时，结果为未完成，不能直接据此判定业务不兼容。开发中可指定 `--baseline-ref HEAD`，对比当前已提交代码与工作区；发布升级核查应明确选择对应的旧版本。

PDF默认选择最多3份代表账单，优先覆盖不同来源及较多明细的账单。使用 `--pdf-samples all` 核对全部历史账单PDF；不能用0或none跳过。HTML、Excel、存储快照及完整账单行均覆盖所有账单，PDF抽样不等同全部PDF验证。默认每版核查超时900秒，可用 `--timeout` 调整；两版依次执行，进程失败或超时不报告通过。

此工具依赖已安装的项目Python运行时、openpyxl、pypdf及现有PDF渲染环境；不自动安装依赖。它不纳入默认检查或发布门禁，不读取约定路径中的生产库，只有显式提供输入路径才运行。

## 输入与隔离

- 输入必须是稳定、完整的离线SQLite备份；非空WAL或journal拒绝处理，不能通过忽略伴随文件取得不完整视图。
- 输入以immutable只读连接备份；运行前后核对主文件、WAL、SHM和journal的大小及SHA-256，运行期间变化则核查无效。
- 输出必须是仓库外尚不存在的新目录，不覆盖历史证据、仓库、数据库或其祖先目录。目录权限0700，副本及报告0600。
- 基准与当前代码各用独立数据库、运行时目录和子进程；覆盖数据库与附件、日志、缓存、IACUC路径配置，清空真实远端凭据，不启动应用后台工作线程。
- HTTP验证只绑定回环随机端口，临时账号和会话仅写入副本；不在报告中保存会话令牌。结束时关闭测试HTTP服务；取消或超时终止本次子进程。
- 核对当前工作区应用及核查工具文件指纹；运行期间代码发生变化，不复用本次成功结果。

## 核查范围

1. 按输入原列和记录身份检查所有原业务表，支持复合主键、无rowid表及可空主键兼容；原记录缺失不能通过。
2. 检查SQLite完整性与外键，比较启动迁移后的原字段投影；新增兼容字段不当作原字段丢失。
3. 完整读取审计正文，包括压缩块校验；原明文审计另作独立参照，原审计在初始化和HTTP核查后均须保持语义一致。
4. 比较所有账单版本及完整行、头金额、行金额总和和最终累计值；HTML逐份比较，Excel比较单元格内容、类型、公式、金额格式及合并区域，PDF比较每页提取文本和页数。
5. 根据实际数量表、技术服务明细，以及已登记月份和占用起始月份中的动态笼位记录重新预览核算；历史源表已不存在的单据读取原快照，不强行从不存在的源记录重新计费。比较时只移除新预览的临时ID和生成时间，不移除历史日期、金额或源版本。
6. 通过真实HTTP查询原接收、数量表、流程、完整行、审计、公开笼卡，以及管理员和房间管理员的代表性读取；流程列表保留原状态筛选，历史详情另逐条核对。
7. 执行原应收GET同步，在副本上比较有效应收、同步后原记录和新增审计事实；不硬编码应同步几条记录。新生成记录的随机ID／时间，以及确实发生同步的应收更新时间单独规范化，其业务键、金额、来源、历史日期及审计前后内容仍需一致。
8. 保留账务及历史关联问题分类，未修复的历史问题继续作为警告展示，不自动销项或修改业务事实。

数据库外附件、外部服务、浏览器版式、生产部署及输入中没有包含的后续实际记录不在覆盖范围。PDF文本及页数相同不证明像素级布局相同，相关浏览器、打印和多页版式回归仍按测试契约执行。

## 结果与退出码

输出包含 `report.md`、`report.json`，以及两版的代码、数据库、完整结果与日志；这些文件含业务信息，只保存在私有验证目录，不提交到Git。

- 退出0：`passed` 或 `passed_with_warnings`，两版核查完整且一致；后者仍有既有历史问题，不表示所有业务数据无异常。
- 退出1：差异、未完成、阶段错误、超时、输入或代码变化。失败证据保留，不能把空结果当作通过。
- 退出2：无效输入或输出路径等参数拒绝；不覆盖已有文件。

核查工具是兼容验证，不替代并发写入测试。旧入口的可选版本规则、写锁及审计事务见 [write-safety.md](write-safety.md)；单次通过不授权推送、发布或生产数据操作。
