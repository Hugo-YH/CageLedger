# 文档与维护入口

本目录面向开发与维护人员，用于定位当前工程契约、专项资料和历史证据。先从[当前实现与兼容边界](contracts/current-baseline.md)核对事实，再按任务进入契约；使用、部署和开发指南的公开源文件在 `wiki/`，由 VitePress 构建到应用 `/docs/`。

## 按读者选择入口

| 目标         | 文档入口                        | 用途                                           |
| ------------ | ------------------------------- | ---------------------------------------------- |
| 使用系统     | [Wiki 首页](../wiki/Home.md)    | 当前业务导航、操作指南与更新记录               |
| 部署与维护   | [运维导航](../wiki/运维导航.md) | 安装、配置、权限、数据、备份与故障处理         |
| 开发与交付   | [开发导航](../wiki/开发导航.md) | 环境、结构、前后端、质量与发布                 |
| 查阅工程约束 | [契约索引](contracts/README.md) | 模块、写入、状态、UI、测试与交付的唯一规则入口 |

## 区分当前规则与历史资料

| 位置                                                      | 内容与使用边界                                                 |
| --------------------------------------------------------- | -------------------------------------------------------------- |
| [`contracts/`](contracts/README.md)                       | 当前规则与事实核对，按任务读取，不复制平行验证矩阵             |
| [`archives/`](archives/README.md)                         | 历史计划、决策与验收，保留当时版本、失败和未验证项             |
| `plan/`、`progress/`                                      | 原有历史路径的兼容索引；新任务仅在需要交接时建立范围明确的记录 |
| `analysis/`                                               | 专项分析和资料，结合各文件的日期与源码基线阅读                 |
| [媒体维护](media/README.md)                               | 截图采集、原创图示、图注与引用来源的统一维护                   |
| `templates/`                                              | 按需使用的记录模板，不要求每次修改填写                         |
| [性能清单](PERFORMANCE_TODO.md)、[演示记录](DEMO_PREP.md) | 历史索引，不证明当前环境已有对应数据或仍有相同待办             |

## 维护与生成规则

当前分支、提交和版本从实际 Git 与 `package.json` 读取。验证矩阵统一维护在[测试策略](contracts/testing-strategy.md)，文档分层、来源和同步规则统一维护在[文档系统契约](contracts/documentation-system.md)。

Wiki 接口清单由 `api-inventory.json` 与生成脚本维护，系统内更新记录由 `wiki/更新日志.md` 生成；不要手工修改派生文件。历史资料只供追溯，不改变当前任务和授权：提交推送、标签、Packages、Release、latest 与生产部署分别按当前约定执行。
