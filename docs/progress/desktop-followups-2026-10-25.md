## 原失败记录与 Firefox 诊断历史

- 初始外置观察配置有模块路径、服务工作目录错误，发生在应用用例启动前；随后导航选择器未包含菜单图标的可访问名称。已修正，原失败目录保留，不计作应用缺陷。
- 首轮新增用例 5/8 通过。两项是控件操作时序：等待筛选选项完成后点击并确认勾选；Select 的 Home 不代表选择首项，改为实际方向键选择。另一项是真实的动态页码缩减问题，已修复并完成全部 8 项复验。
- 页码诊断日志记录：新响应为第 3 页、有效页数 1 时，旧回调仍读到初始第 1 页/1 页；最终代码移除临时诊断输出。未将原因扩大为未经验证的 React 库缺陷结论。
- Firefox 原生滚轮控制曾暴露测试提前取值、hover 自动滚动等时序问题；这些控制失败及 trace 全部保留。没有通过增大预算、忽略控制台、删断言或加自动重试来变绿。
- 最终采用原可复现的滚动定位测试；其全部业务断言可完成，但 Firefox 报告 “scroll-linked positioning effect” 警告。随后在干净、无本轮修改的 `5223ae7` 上，以独立服务和相同严格控制台检查复现同一警告（`firefox-clean-baseline-ready`）。首次基线控制遇登录未完成的导航竞态，也单独保留。
- 已证实该警告并非本轮独有；尚未量化它在真实使用中的性能影响，不将其称为无害，也不将它写成已修复。本轮未扩展为全局滚动系统重构。该原生诊断已在下方收尾中与运行异常精确分类，功能验收现已闭环；没有关闭浏览器提示或泛化忽略警告。

## 收尾修复与最终定向验收

收尾应用/测试提交为 `9aa492ff80292e2452a54bd1bacf59faaeb30da1`，位于同一独立分支，未修改计费、权限、API、数据库或版本。

1. **警告定位与分类。** trace 中提示出现在分页选项选择期间，早于记录勾选、测试设定滚动位置和返回恢复，不能将它归因于本轮恢复逻辑。发布版也可复现。按 [Mozilla 原生诊断语义](https://firefox-source-docs.mozilla.org/performance/scroll-linked_effects.html)，这是检测滚动关联效果的性能提示，不是未捕获的应用异常；提示本身不能证明真实帧率或实际卡顿。下拉去虚拟化、局部禁用自动锚定的控制未能稳定解决问题，均已撤回，未作为成果保留。
2. **真实位置边界。** 一次复验出现 180px 恢复后变为 150px。跟踪确认导航捕获值和应用写入值均为 180px，后续布局仍可能调整位置。`useWorkspaceScroll` 改为先等待表格测量帧、再一次性恢复；只增加一个渲染帧，不加固定超时、滚动监听或重复恢复。两帧都能在卸载/未就绪时取消，恢复后不覆盖后续用户滚动。精确像素断言未放宽，并新增后续两帧仍保持同位置的断言。
3. **保留真实错误能力。** 仅 Firefox、完整已知原生包装文本、当前应用文档 URL、零行号与原生列号同时匹配时，将记录保存为 `native-browser-performance-diagnostics` 附件。任何其他引擎、来源、文字、普通 `console.warn`、`console.error` 或页面异常仍失败。10 项分类器单测覆盖反例；三个引擎还真实注入应用同文告警、普通告警、错误和未捕获异常，验证不会误归类。已实际捕获的原生提示见 `closure-retained-native-diagnostics.json`，未从证据中删除。
4. **原生滚动观察。** 桌面真实键盘/滚轮操作后，24 个渲染帧样本中工具栏顶部位置稳定，键盘焦点保留。Firefox 观测窗口中工具栏顶部读数均为 24 CSSpx；这是有限窗口的几何/焦点检查，不等同全程滚动帧率或所有性能场景认证。
5. **页码缩减再核实。** 已保存数量表的 24 条结果从第 3 页缩至 3 条后，返回第 1 页并显示 3 行；失败不会被当作零条，取消后的迟到响应不能替换当前结果。单据跟踪原有 remembered-page 缩减用例也重新通过。`useListPageBounds` 的前一批修复确实存在且在最终生产代码上验证。
