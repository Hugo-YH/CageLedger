# 异常动物（大动物）评估开发资料

本目录保存“动物管理 → 动物巡检 → 异常动物（大动物）评估”的前期整理资料，当前仅作为开发输入，尚未接入巡检目录、数据库或生产页面。

## 已导入内容

- 目录草案：Markdown 与 HTML 各 1 份
- 参考图片：51 张
- 涉及物种：猴、兔、普通级豚鼠、犬
- 一级分类：整体状态与行为、被毛与皮肤、头颈部、胸部、腹部、四肢、尾巴、繁殖

资料位于 [`resources/`](resources/)。Markdown 草案保留原有相对路径，可直接打开图片链接；
[`manifest.json`](resources/manifest.json) 记录每个文件的来源哈希、开发副本哈希、尺寸和体积。

## 图片处理

桌面原图约 131 MB，部分文件包含手机型号和精确 GPS 坐标。导入仓库的是开发副本，处理规则如下：

- 保持原有目录和文件名，桌面原件不作修改。
- 最长边限制为 2048 px，JPEG 质量为 85。
- 删除 EXIF、GPS 和拍摄设备信息。
- 单张图片均小于巡检参考图 5 MB 的上传限制。
- Markdown 和 HTML 只做格式化，不改动目录内容与图片引用。

开发副本约 19 MB。后续若确认发布，可从这里生成运行时种子资源，不应直接从桌面原图写入 `server_app/resources/animal_inspection/v1/`。

## 内容边界

草案按现场可见表现组织，适合作为巡检记录和升级处置的初始目录，不代替兽医诊断、治疗方案或伦理终点判断。
文件名中“原标记低血糖”“原标记耳螨”“原标记白内障”等内容只保留资料收集时的线索，不能直接作为系统诊断结论。

正式接入前仍需确认：

1. 大动物模块是否复用现有二元结论“正常/异常”，以及异常后的处置流程。
2. 猴、兔、豚鼠和犬是否共用一套目录，还是按物种隐藏不适用条目。
3. A/B/C 处置时效是否进入结构化字段，最终阈值由谁审核和发布。
4. 参考图是否全部允许进入生产系统，以及水印、拍摄日期和设施背景是否需要进一步处理。
5. 新模块使用独立 `moduleCode`，不得复用当前小鼠模块 `abnormalAnimalAssessment`。

## 后续接入位置

确认业务规则后，实施工作应沿用现有巡检目录契约：

- 模块与节点：`server_app/resources/animal_inspection/`
- 目录结构校验：`server_app/domains/animal_management/catalog_schema.py`
- 前端类型：`src/contracts/animalManagement.ts`
- 巡检录入：`src/react/features/animal-management/`
- 参考图运行目录：`data/animal-inspection-images/`

目录发布仍需经过草稿保存、管理员审核和版本发布流程，不能直接修改当前 active 目录。
