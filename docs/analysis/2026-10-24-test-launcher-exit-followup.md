# 测试进程残留收尾复查

本次针对用户再次提出的测试服务退出残留做有限复查，未重做 PDF 模块。分支仍为 `codex/performance-post-1.17.1`；原修复 `1d93dec`、报告 `84f840b` 均在当前祖先链中。[上一批 PDF 验收](2026-10-24-pdf-renderer-lifecycle.md)保留，本批最小应用/测试修复为 `57fe42d`。

## 实际遗漏与修复

主开发服务、PDF renderer 和普通/兼容 Playwright 服务的正常退出修复已经存在。但 `scripts/run_python.mjs` 没有处理启动器收到的 SIGINT/SIGTERM。它作为测试、运行和检查 Python 的共同入口，单独正常停止该 Node 启动器时，Python 子进程没有收到退出信号。

在新生成数据库、回环地址的最小真实 PDF 复现中，停止旧启动器后退出码为 -15，留下 9 个已由实时父子链登记的自有进程：Python、Playwright 驱动和浏览器后代。仅向身份、启动时间和进程组均匹配的自有 Python 发送 SIGTERM 后，9 个后代全部退出。初始红例和正常清理记录保留。

修复仅向持有的 ChildProcess 句柄转发一次原信号，等待子进程完成退出，重复信号不再中断清理；未增加全局 PID 搜索、强杀或系统设置变更，正常子进程失败码仍保留。扫描器专项的第二个构建预览服务也补上 SIGTERM / 150 秒宽限，使其与 API 服务一致；没有改变业务断言、性能阈值或启动预算。
