# 全系统 UI 反馈用途盘点（2026-11-02）

本文件保留通知迁移前的源码用途盘点，并在文末登记本次迁移落实。表格和“迁移前拆分点”基于 `main` 的 `98b942e` 及当时未提交工作区，结合 Ant Design `6.5.2` 源码核对；它们描述迁移前状态，不代表现行代码。未做生产实测或部署，现行开发遵循 [UI 反馈分类契约](../contracts/ui-feedback.md)。

分类按反馈用途确定，不按组件名称、变量名或 `role="status"` 机械替换：

- **N — Notification**：右上角单次操作结果和长任务生命周期；长任务复用现有 TaskFeedback。
- **M — Message**：顶部居中的轻量本地反馈，如复制、选择限制、尚未提交的编辑操作。
- **A — Alert**：当前页面或弹窗内持续可见的上下文、风险、加载失败和重试依据。
- **X — 非三类通知**：Form 字段校验、Modal/Popconfirm 确认、Skeleton/Empty/Result、Tag/Tooltip 状态，以及普通业务内容。

纯请求失败如需留在当前表单中重试，优先使用 A；同一段错误不同时用 N 和 A 重复报告。操作结果与需要持续核对的差异、失败明细可以分别呈现，但文案和职责必须不同。以下表格中的“当前呈现”和“建议”保留为迁移前基线，落实情况见文末。

## 迁移前缺口与拆分点

1. **全局任务反馈与局部提示重复。** PDF 已复用 `src/react/components/TaskFeedback.tsx`，但数量统计表、预览和结算列表仍有局部进度/错误提示。应保留有用的按钮进度与恢复入口，并按 N/A 职责消除同一段结果或错误的重复报告；TaskFeedback 的右下角位置尚未迁移。
2. **成功提示依赖已关闭的表单。** `billing/hooks/useQuantitySheetEditor.ts` 保存编辑内容会关闭编辑弹窗，成功 notice 仍归表单；后续迁移需要在真正保存成功时报告 N。接收、技术服务等同样要核对成功回调与弹窗退出生命周期。
3. **多个 notice 混合语义。** `intake/IntakeView.tsx`、`billing/hooks/useQuantitySheetEditor.ts`、`billing/components/SettlementCandidateList.tsx`、`workflows/components/BillingWorkflowPanel.tsx`、`cages/CagesView.tsx`、`animal-management/InspectionEntry.tsx` 需要先分离操作结果、进行中状态、字段问题、选择指引和部分失败，不能直接将 setNotice 替换为 notification。
4. **合格证错误承载多个阶段。** `reception/ReceptionCertificateDrawer.tsx` 的 error 包含文件校验、明细校验、上传、识别与保存失败。`reception/ReceptionCertificateReview.tsx` 的人工核对、版本变化、只读权限与差异必须继续局部可见；识别完成不能称为登记已确认保存。
5. **主体成功与附件失败混在一条结果中。** `animal-management/InspectionEntry.tsx` 把照片失败拼入巡检提交结果，且提交时先调用草稿保存；后续需避免中间保存成功和最终提交成功连续弹出。`feedback/FeedbackCreateDrawer.tsx` 与 `feedback/FeedbackDetailDrawer.tsx` 的正文已保存、截图待重试状态也必须保留，不能一律标为纯成功或纯失败。
6. **报销与部分导出存在显式反馈缺口。** `workflows/components/ReimbursementClaimDialog.tsx` 的保存/附件上传、`workflows/components/LedgerReconciliationPanel.tsx` 的核销创建/确认/撤销，在组件中未提供一致结果反馈；`animal-management/InspectionDetailDialog.tsx` 直接发起 PDF 下载，没有显式任务结果。此处记录待整改线索，尚未补齐实现。
7. **登记、经费风险和状态推进不可合并。** `workflows/components/WorkflowRegistrationModal.tsx` 与 `workflows/components/WorkflowReimbursementRecordingModal.tsx` 的保存、附件、字段校验、经费本来源不可用与经费归属确认需要独立处理。接收日期确认、重复批次确认、检疫出具/完成确认同样保留 X。
8. **同步与发布必须按真实完成状态措辞。** 反馈同步请求已受理不等于 Gitea 已同步，巡检目录本地移除不等于草稿已保存，保存草稿不等于目录已发布；状态标签、版本差异、批量失败明细、冻结和只读约束不属于瞬时操作结果。

当前 React 设置源码未发现独立的“计费规则编辑”或“立即同步”页面入口。现行相关设置分布在房间计费配置、负责人身份/免费额度、功能开关与业务表单中，Gitea 同步位于反馈模块；不能根据历史更新记录补造现行操作或通知。
