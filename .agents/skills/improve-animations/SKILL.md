# 动效审计与改进

根据用户请求决定交付审计、方案还是实现。限定目标页面或模块，查看现有动画、Token、触发频率与用户影响；无需默认扫描整个仓库。

- 审计维度参考 [AUDIT.md](AUDIT.md) 的相关条目：目的、频率、缓动、时长、连续性、性能、无障碍和一致性。
- 项目契约和实测证据优先于参考中的审美阈值、推荐曲线和库；区分可复现问题与待浏览器确认的假设。
- 按影响排序报告文件位置、触发场景、问题和建议；无问题时直接说明，不凑数量。
- 用户要求方案时可用 [PLAN-TEMPLATE.md](PLAN-TEMPLATE.md)，记录当前代码位置、目标行为和验证方式；不为单个小修正生成整套计划目录。
- 用户已要求修复时继续实现和目标验证，不停在发现列表等待再次选择。仅审计时不修改应用源码；存在实质性的产品取舍才澄清。
- 不自动委派其他模型或创建任务；需要独立并行工作时遵循当前会话的工具与授权规则。
