# 测试与质量

本页面向开发者和验收人员，帮助从本次 diff 选择检查入口，并据实际结果交付证据。先确认改动影响的现役页面、接口或兼容能力，再选择能验证行为的最轻层；完整验证矩阵、资源保护和结果复用统一维护在仓库 `docs/contracts/testing-strategy.md`。

## 从改动选择验证

1. 沿[当前版本与兼容边界](/development/current-baseline)确认实际入口，列出受影响消费者。
2. 判断风险：文字与布局、纯计算、React 交互，或涉及权限、结算、迁移、打印的跨层行为。
3. 选择明确文件、模块或用户路径。静态依赖不能覆盖动态加载和跨语言关系时，补充对应目标。
4. 集中完成改动后执行一次相关验证，保留范围与结果。只有新改动、失败或未解决风险才扩大或重复检查。

纯文字修改检查受影响文件的格式、Markdown lint、链接和 diff；文档导航、结构或渲染能力变化时按需构建文档。权限改动覆盖管理员与房间管理员，关键写入同时核对 SQLite 和审计。打印与结算汇总按契约验证前端模板及 Python PDF 的等价结果。

## 指定目标的日常入口

以下是选用示例，目标应按实际改动替换，不需要逐条全部运行：

```bash
npm run test:target -- src/domain/intake.test.ts
npm run test:related -- src/domain/intake.ts
npm run test:python:target -- tests.test_api_inventory
```

上述入口缺少目标会拒绝执行，零匹配不能记作通过。`test:related` 依据静态依赖选择测试；后端路由、共享 fixture、动态入口和跨语言契约需要人工补充范围。新增测试验证用户行为或业务规则，避免只匹配文案或复述实现。

## 较大范围的工具入口

| 命令                     | 实际范围与使用场景                                                            |
| ------------------------ | ----------------------------------------------------------------------------- |
| `npm run check:docs`     | 构建 VitePress 文档；用于文档结构、导航和渲染检查                             |
| `npm run verify:quality` | 格式、lint、类型与项目契约；不运行测试或生产构建                              |
| `npm run check`          | 静态质量与全部 Vitest／Python 测试；显式选择该完整范围时使用                  |
| `npm run build`          | 统一构建 React 应用和 VitePress 文档                                          |
| `npm run smoke:api`      | 管理员与房间管理员 API 冒烟，按相关接口评估覆盖                               |
| `npm run test:e2e`       | Playwright 用户流程与 Axe 可访问性检查                                        |
| `npm run benchmark`      | 列表、结算与大型笼位图性能基准                                                |
| `npm run verify:full`    | 基础质量及全量单元/API、共享构建、Chromium 完整回归、Firefox／WebKit 兼容专项 |

日常提交和推送复用同一源码状态的有效结果，不自动触发全量、构建或打包。云端发布默认按风险补齐质量、相关回归和产物冒烟；共享基础变化、高风险改动或明确要求时升级完整范围。Mac 手动备用的完整发布配置保留其自身门禁，见[发布与交付](/development/release-and-delivery)。

## 运行隔离与结果判定

Python 命令通过项目 `.venv` 的 Python 3.13 执行。浏览器回归使用独立端口和临时 SQLite，保持宿主锁、资源保护、单组浏览器和单 worker。不要直接调用内部 `check:steps` 或后台拼接多组重任务来绕过受管入口。

检查报告应列出实际范围、通过／失败／未运行项及限制。资源中止、零用例、引擎缺库、跳过或重试直到变绿不能称为通过；完整跨浏览器验证只有在覆盖清单、结构化报告和退出码均有效时才成立。结束时核对本次服务和浏览器退出，相关约束见测试策略。

提交前运行 `git diff --check`。格式与 lint 的工具职责见仓库 `docs/contracts/code-quality.md`，恢复演练见[备份与维护](/operations/backup-and-maintenance#在隔离目录演练恢复)。
