# 后端架构

本页面向修改 API、业务事务和持久化逻辑的开发者。从路由登记追踪 handler、领域 service 和 repository，明确鉴权、事务、审计与缓存失效的边界。后端使用 Python 3.13 标准库 HTTP 服务和 SQLite，生产同时提供应用、文档与 API。

## 服务结构与职责

<DocFigure src="/diagrams/system-architecture.svg" kind="diagram" alt="React 应用、文档与 API 在生产服务汇合，领域服务访问 SQLite、附件和文档转换器" caption="先区分浏览器、应用服务与持久化资源，再核对数据库写入、文件下载及转换器依赖。" />

| 层次       | 主要路径                                      | 职责                                        |
| ---------- | --------------------------------------------- | ------------------------------------------- |
| 启动与装配 | `server.py`、`server_app/legacy.py`           | 启动、依赖装配及历史导出兼容                |
| HTTP       | `server_app/web/`                             | 路由登记、鉴权、参数、状态码与响应          |
| 领域服务   | `server_app/domains/`                         | 业务规则、跨表事务、审计与缓存失效          |
| 数据访问   | 领域 repository、`server_app/repositories/`   | SQL、分页、结构化热字段与 payload 兼容      |
| 基础设施   | `config.py`、`db.py`、`cache.py`、`static.py` | 配置、连接、短缓存、静态资源与 SPA fallback |
| schema     | `server_app/persistence/`                     | 幂等建表、字段和索引补齐、旧库回填          |

新增业务进入 `server_app/domains/`，不继续扩大兼容层。`server_app/services/` 仍提供在用的兼容导出，不能按目录名推定其已退出生产。

## 处理一次写入

1. 从 `server_app/web/router_registry.py` 找到路由登记和实际 handler。
2. handler 核对会话、角色、资源归属及输入，调用领域 service。
3. service 完成业务校验，在事务中调用 repository，并记录审计。
4. 写入成功后失效受影响缓存，返回最新对象及相关变化；失败不得留下部分业务结果。

接口、错误响应及幂等规则见 [API 与数据模型](/development/api-and-data-model)和仓库 `docs/contracts/api-contracts.md`；资金、跨房间转移、权限与迁移遵守 `write-safety.md`。新增或调整路由后同步生成[接口清单](/development/api-inventory)。

## 数据库与运行目录

SQLite 启用 WAL。源码启动且未覆盖路径时，数据库为 `data/database/cageledger.sqlite`；镜像显式设置 `/app/data/cageledger.sqlite`。`CAGELEDGER_DB`、`CAGELEDGER_DATA_ROOT` 及附件路径覆盖的关系见[部署与运行](/operations/deployment#确认数据实际写在哪里)，备份必须按运行配置定位。

启动时执行幂等 schema 初始化、索引创建和必要回填。高频列表使用服务端分页、筛选和稳定排序，热点字段使用实体列，避免依赖 JSON 全表扫描。修改迁移要验证旧库兼容；修改关键写入要同时核对 SQLite、审计和缓存，不能只验证 HTTP 成功。

## 兼容接口与现役流程

当前报销登记与补录使用 `/api/billing-workflows/*`。旧 `/api/reimbursement-ledger/*` 等接口仍受支持，保留资金、归属、权限和审计规则；数据管理仍使用历史报销台账 Excel 导入。前端旧页面未挂载，不等于后端能力可删除。

接口支持状态和 UI 可达性分别记录在[当前版本与兼容边界](/development/current-baseline)与[接口清单](/development/api-inventory)。`legacy.py`、旧字段和 payload 的删除必须有明确迁移方案。

## 文件、转换器与退出

附件保存在 `data/files/` 的分类目录，经鉴权 API 下载。检疫资料与各版本 Word、反馈截图及远端关联需要和数据库共同维护，见[备份与维护](/operations/backup-and-maintenance)。

PDF 任务复用常驻 Chromium，缓存默认位于 `data/cache/pdf/`；Word 预览使用 LibreOffice Writer，合格证 PDF 处理使用 Poppler。生产镜像预装相关依赖和中文字体，运行依赖版本由 `requirements-runtime.txt` 与 `runtime-image.lock.json` 固定。

退出时先停止接收请求，再由 PDF 工作线程关闭自己持有的浏览器与 Playwright 驱动。定位转换或清理故障时，保留请求 ID 和日志证据，按[故障排查](/operations/troubleshooting)处理。
