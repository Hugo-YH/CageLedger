# 开发规范

本页约束代码修改、测试、文档和发布。Codex 云端负责日常开发、验收、按影响范围的测试和交付任务的软件包构建；代码及产物推送到 Gitea，由 Gitea 托管代码和软件包。Mac mini Runner 仅作可选手动备用。

## 开发基线

- Node.js `>=22.12.0 <23`，Python 3.13。
- 依赖安装使用 `npm ci`；Python 先用 `python3.13 -m venv .venv` 建立虚拟环境，再运行 `.venv/bin/python -m pip install -r requirements-dev.txt`。
- React 页面使用 TypeScript。
- 服务端业务数据使用 TanStack Query。
- 本地 reducer 管理界面偏好。
- Python 后端保持 HTTP、service、repository 分层。
- SQLite 迁移保持幂等和旧库兼容。

## 前端规则

1. 页面通过 typed API hooks 访问服务端。
2. 查询键集中在 `queryKeys.ts`，mutation 精确失效相关根键。
3. 高频输入保留局部草稿，输入过程中避免整页查询失效。
4. 跨页面可复用计算进入 `src/domain/` 并补 Vitest。
5. 业务页面通过现有懒加载入口接入。
6. 预览与打印共用 `src/react/print/` 模板。
7. 操作反馈按 `docs/contracts/ui-feedback.md` 分类使用 Notification、Message、Alert；业务确认继续使用站内确认弹层。全系统用途盘点和迁移边界由该契约提供入口。
8. 页面优先使用 `src/react/components/ui/` 与 Ant Design 原语；颜色、按钮、表单和弹窗遵守 `docs/contracts/ui-component-standard.md`。
9. 工作区的“系统更新”按版本顺序汇总当前账号上次确认之后的更新；无确认记录时仅展示当前版本。批量确认成功才关闭，旧单版本记录继续兼容。确认状态按账号和版本保存在服务端，内容来自 `wiki/更新日志.md` 的生成数据。

## 后端规则

1. handler 负责鉴权、参数、状态码和响应。
2. service 负责业务校验、事务、审计和缓存失效。
3. repository 负责 SQL、分页、索引和 payload 兼容。
4. 高频列表使用结构化列和服务端分页。
5. 写入接口返回最新对象和受影响对象。
6. schema 新增字段和索引时补自动迁移与旧数据回填。

开发服务通过 Ctrl+C 或 SIGTERM 正常退出；启动器等待自己启动的 API、资源与文档子服务结束后，再删除临时数据库目录。API 退出先停止接收请求，再由 PDF 工作线程关闭自己持有的浏览器和 Playwright 驱动。初始化失败也走同一清理入口，退出开始后不再接收新的 PDF 任务。

Playwright 隔离服务使用 SIGTERM 收尾，最多等待 150 秒；这只影响服务退出等待，不改变启动、业务断言和性能阈值。不要用进程名批量清理浏览器，也不要将强制退出、系统终止或浏览器无响应视为已保证清理的路径。

`scripts/run_python.mjs` 收到 SIGINT/SIGTERM 时只向自己启动的 Python 子进程转发一次，并等待其退出；正常子进程失败状态仍原样返回。扫描器专项的 API 与构建预览服务都使用同样的 SIGTERM 收尾宽限。

## 业务规则

- IACUC 是笼卡、占用、统计表和结算的核心键。
- Animal Record ID 是笼卡实例的持久唯一标识。
- `项目来源` 是 `funding` 的 source of truth。
- 数量统计表是当前启用的结算入口；动态笼位图结算按发布状态单独开放。
- PI 减免需要同时考虑总额度、IACUC 有效期、优先减免和逐日分配。
- 当前报销登记与补录在单据跟踪完成，登记与锁定归档分别表达；旧台账和核销接口保留兼容，不作为当前页面。
- 权限变化同时验证前端入口和后端校验。

## 验证

开发中按改动范围选择检查，统一矩阵维护在 `docs/contracts/testing-strategy.md`。纯文字修改检查修改文件的格式、lint、链接与 diff，不默认文档构建；文档结构或配置变化按需验证构建。React 交互验证目标页面；API、权限、缓存与迁移保留相关 API 冒烟和双角色验证；打印、性能与关键业务链执行对应回归。

日常提交和推送完成针对性验证即可，简单修改不运行完整 `npm run check`、`npm run verify:full`、生产构建或打包。交付按风险验证；完整回归仅在明确要求或共享基础变化需要时执行；高风险改动按影响范围补充相关回归。检查通过后，只有新改动、失败或未解决风险才需要重跑或扩大检查。

## 工具链

- Prettier：TS、TSX、CSS、JSON、YAML 和活动 Markdown。
- ESLint：TypeScript、React Hooks、React Refresh 和 JSX 可访问性。
- Stylelint：CSS 标准语法、未知值和重复声明。
- Markdownlint：标题、列表、代码块和链接。
- Ruff：Python 格式、import 和 lint。
- Playwright + axe：关键业务链和 serious/critical 可访问性回归。

静态质量检查为 `npm run verify:quality`；`npm run check` 另含全部单元/API测试，`npm run verify:full` 再包含构建和浏览器完整范围。云端交付按改动风险选检查并复用有效证据。Codex 云端按 cgroup 配额受管执行；可选 Mac mini M4 16GB 完整正式发布配置保留三片 Chromium 和独立兼容结果，一次仅一组浏览器、每个测试库单worker，完整报告汇总通过才继续该配置的发布。详细规则见 `CONTRIBUTING.md`、`docs/contracts/code-quality.md` 和 `docs/contracts/testing-strategy.md`。

## ARM64 云端交付

生产运行环境由 `runtime-image.lock.json` 固定，`requirements-runtime.txt` 冻结生产 Python 依赖。普通应用构建复用相同依赖层，变更依赖后才显式执行 `npm run runtime:refresh` 并提交新锁。运行环境刷新使用内容寻址标签，不移动应用版本或 `latest`；应用与运行环境的同摘要层由 Registry 复用。

日常发布继续推送 Gitea Packages，Release 默认只附来源/镜像摘要与拉取指引。只有明确需要离线交付时，使用 `npm run release:cloud -- --offline-image --publish` 上传完整镜像分片；不上传离线源码包。生产通过 Docker 增量拉取，部署和回滚另行授权。云端入口、Registry 凭据及恢复方式见仓库 `docs/contracts/cloud-development.md`。

## 版本编号规则

- 版本格式 `a.b.c[-betaN | -rcN]`：`a` 重大/代际版本，`b` 功能更新，`c` 补丁修复；`-betaN` 内测后缀，`-rcN` 公测后缀，正式发布去掉后缀。
- 构建标识 `build` 为纯数字构建号，从最早记录 `0.2.0（Build 1）` 起按发布顺序逐次递增，带后缀的小版本（如 `0.5.16a`、`0.5.16b`）各占一个 build，随每次发布由发布脚本推导并写入 `package.json`。
- 系统展示格式为 `a.b.c（Build N）`，`N` 为 `build`；页脚、系统设置与 `/api/health` 使用同一来源。
- 软件包 tag 只带版本号：Git tag `v<version>`、容器镜像 tag `<version>`；build 不进入软件包 tag。
- 版本唯一源为 `package.json`；`scripts/set_version.mjs` 同步 `index.html`、`src/react/version.ts`、`wiki/更新日志.md` 与部署文档。

## 发布与当前事实

正式云端交付以[发布与交付](/development/release-and-delivery)及仓库 `docs/contracts/cloud-development.md` 为准。先准备版本、最终源码验证、提交推送、ARM64 产物与冒烟、附注标签和 Packages 核验，再运行 `npm run release:cloud -- --publish`。该命令不代替前述准备步骤；不自动部署 NAS，也不更新 latest。

`release:local` 保留独立的 Mac 完整正式发布配置，平台专用检查和 Gitea origin 要求不套用到云端检出。普通修改按实际影响验证并备份到 Gitea，不自动打包或发布。

页面是否现役先核对[当前版本与兼容边界](/development/current-baseline)，再追踪实际入口与调用链。`npm run check:frontend-lifecycle` 检查历史组件登记与生产依赖图；类型引用、孤立测试、兼容导出不能证明当前菜单可达。后端 API 是否保留与 UI 是否仍使用分开判断。

代理入口为仓库 `AGENTS.md`。验证范围、宿主锁、资源保护与证据复用只在 `docs/contracts/testing-strategy.md` 维护；指令维护规则见 `agent-instructions.md`，不恢复归档任务和旧授权。
