# 本地开发

本页面向首次运行项目或维护开发环境的开发者。从仓库根目录安装依赖、启动隔离数据环境后，应能访问应用、API 和同一套 Wiki 文档；随后按改动范围选择验证。云端认证和远端同步另见仓库 `docs/contracts/cloud-development.md`。

## 1. 准备运行时与依赖

项目使用 Node.js `>=22.12.0 <23` 和 Python `3.13`，分别以 `package.json`、`.nvmrc` 和 `.python-version` 为准。先确认版本，再执行：

```bash
npm ci
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

项目脚本使用 `.venv` 中的 Python，不回退到系统 Python。已有其他 Python 3.13 环境时，通过 `CAGELEDGER_PYTHON_BIN` 指定解释器；`scripts/check_python_runtime.mjs` 负责校验解释器版本。虚拟环境隔离方式可参考 Python 官方说明。<sup>[1](#参考资料)</sup>

涉及 PDF、Word 预览或合格证解析时，还需要 Chromium、中文字体、LibreOffice Writer 和 Poppler。生产镜像已经包含这些组件；开发机应根据目标功能准备，不能把 Python 依赖安装成功视为所有转换器均已就绪。

## 2. 启动并确认三个服务

首次体验、截图或调试时，优先使用隔离数据：

```bash
CAGELEDGER_EPHEMERAL_DB=1 npm run dev
```

该模式把 SQLite、附件和索引放入临时目录，并隔离真实 Gitea、AI 凭据；正常退出后清理临时数据。需要保留日常开发数据时运行 `npm run dev`，未覆盖路径时使用 `data/database/cageledger.sqlite`。先确认数据来源，再执行写入操作。

| 服务 | 默认地址                           | 确认结果                                         |
| ---- | ---------------------------------- | ------------------------------------------------ |
| 应用 | `http://localhost:5173`            | 门户及 `/app` 工作区可以打开                     |
| API  | `http://127.0.0.1:5174/api/health` | 返回服务健康与版本信息                           |
| 文档 | `http://localhost:5173/docs/`      | 通过应用代理访问 Wiki；VitePress 进程使用 `5175` |

端口被占用时可整体调整：

```bash
CAGELEDGER_DEV_PORT=5183 CAGELEDGER_DEV_API_PORT=5184 CAGELEDGER_DOCS_PORT=5185 CAGELEDGER_EPHEMERAL_DB=1 npm run dev
```

需要连接独立 API 时，用 `CAGELEDGER_API_ORIGIN` 指定代理目标，并先核实目标数据库。隔离模式始终把代理指向本次启动的 API。

## 3. 修改、验证与退出

先沿[项目结构](/development/project-structure)找到实际入口，再阅读对应契约。测试目标和检查范围见[测试与质量](/development/testing-and-quality)，不要以运行完整套件代替判断影响范围。

使用 Ctrl+C 或 SIGTERM 退出开发启动器。启动器会等待自己启动的 API、Vite 和文档子进程结束，再删除临时目录；PDF 工作线程负责关闭自己持有的 Chromium 与 Playwright 驱动。退出后核对本次端口已释放，不按进程名批量终止其他浏览器。

## 4. 按需验证生产运行方式

仅在需要检查生产资源、同源路由或交付时构建：

```bash
npm run build
node scripts/check_python_runtime.mjs
CAGELEDGER_ENV=production node scripts/run_python.mjs server.py
```

首次创建生产管理员前，需在服务环境中配置非空用户名和至少 12 位的随机密码，见[部署与运行](/operations/deployment#本地生产运行)。构建完成后，Python 在 `5173` 同时提供门户 `/`、工作区 `/app`、文档 `/docs/` 和 `/api`；`npm start` 会依次执行构建、运行时检查和启动。

页面或代理异常时，按[故障排查](/operations/troubleshooting)核对端口、第一条失败请求和对应日志。
