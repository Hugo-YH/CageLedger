# 当前版本与兼容边界

本页帮助使用者和维护者区分当前工作台、兼容入口与历史资料。本次核对以 `v1.31.7` / Build 276（2026-11-09，源码 `11c85df`）为基线；后续版本以应用版本、当前源码和[更新日志](/releases/)为准。

## 当前工作台

| 模块                     | 当前入口与用途                                                       |
| ------------------------ | -------------------------------------------------------------------- |
| 总览                     | 接收、房间、待办、异常与饲养费统计；“主页”另行返回项目门户           |
| 笼卡管理                 | 预约消息识别、待接收批次、二维码扫描；图文核对统一在当前核对弹窗处理 |
| 接收管理                 | 接收列表、独立接收登记、合格证原件和识别、接收登记表导出             |
| 检疫管理                 | 检疫批次、寄生虫、ELISA、PCR、报告及供应商历史                       |
| 笼位管理                 | 房间与笼架的笼位图、占用、预留和待进驻任务                           |
| 动物管理                 | 动物巡检、异常处置、巡检记录、巡检标准                               |
| 饲养费管理               | 录入数量统计表、已保存数量统计表；正式饲养费结算使用这些统计表       |
| 技术服务费管理           | 录入技术服务明细、已保存技术服务明细；按实际服务数量独立核算         |
| 结算管理                 | 结算列表、单据跟踪、汇总导出；两类费用各自独立出单                   |
| 实验人员信息、帮助与反馈 | 独立目录、联系方式与反馈工单                                         |
| 系统设置                 | 系统功能、房间、数据与核查、账号、操作日志、系统状态，按角色显示     |

桌面、手机入口和跨页快捷操作受账号权限与系统功能显示配置控制。八组业务开关包含笼卡、接收、检疫、笼位、动物、饲养费、技术服务费和结算管理。开关隐藏入口不撤销后端权限，也不删除业务数据。

## 当前结算与报销流程

```text
数量统计表 / 技术服务明细
  → 结算列表：预览、导出、发起
  → 单据跟踪：已发起 → 已登记 → 锁定（已归档）
```

交回登记和补录报销单都在“结算管理 → 单据跟踪”中完成。登记后仍未归档；授权账号锁定后才显示已归档，解锁恢复原阶段。锁定也允许从已发起阶段执行，后续操作按现有权限处理，详见[结算与报销](/guide/settlement-and-reimbursement)。

**当前工作台没有“结算应收／报销单／核销中心／历史台账”四个独立页签。** 不需要在菜单中寻找这些旧入口。

## 保留的兼容能力

| 保留项                                         | 当前边界                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------- |
| 旧报销、核销前端组件                           | 源码与针对性测试保留，当前工作台不挂载；组件单测通过不代表存在当前菜单    |
| `/api/reimbursement-ledger/*`                  | 兼容 API 仍存在，并保留鉴权、归属、资金与审计规则；不作为当前页面操作入口 |
| `/api/reimbursement-records/*`                 | 旧台账兼容读写仍保留，其中历史 Excel 导入仍由数据管理使用                 |
| 动态笼位图计费                                 | 代码和历史视图保留，默认菜单未开放为正式结算入口；现役笼位管理继续使用    |
| 技术服务独立结算视图值                         | 历史视图值转入共用结算列表，不再另设菜单                                  |
| 旧预约补充弹窗与协议                           | 当前用统一图文核对弹窗；旧弹窗实现与后端兼容协议分别保留                  |
| `server_app/legacy.py`、`services/` 与兼容导出 | 属于仍有装配或调用用途的兼容边界，名称含 legacy 不等于可删除              |

兼容 API 的完整登记见 [API 接口清单](/development/api-inventory)。`supported` / `compatibility` 描述接口支持方式，不描述页面是否可达。删除兼容能力需要核对调用方、历史数据与迁移方案。

## 维护时从哪里核对

- 版本、命令与运行依赖：`package.json`、锁文件及实际脚本。
- 页面入口：`ReactWorkspace.tsx`、`workspaceNavigation.ts`、`MobileNavigation.tsx` 与实际 View。
- 运行时前端依赖及历史实现：仓库 `docs/contracts/frontend-lifecycle.json` 与 `npm run check:frontend-lifecycle`。
- 后端入口：`server_app/web/router_registry.py`、领域 handler/service 与 `docs/contracts/api-inventory.json`。
- 文档和历史：当前说明在 `wiki/` 与 `docs/contracts/`；旧计划、演示及验收在 `docs/archives/`，不代表当前待办、数据或授权。

仓库维护规则见 `docs/contracts/current-baseline.md`。仅靠文件存在、测试 import、旧更新日志或单个关键词，不能判定当前功能与影响范围。
