# 项目结构

本页面向定位代码和评估影响范围的维护者，按「找入口 → 找领域 → 找契约与验证」阅读。目录说明代码职责，当前菜单与兼容状态先看[当前版本与兼容边界](/development/current-baseline)；历史任务记录保留在 `docs/archives/`。

## 仓库全景

```text
.
├── src/                    # React、API 类型、纯业务函数和样式
├── server.py               # Python 服务启动与装配
├── server_app/             # HTTP、领域服务、持久化和文档输出
├── tests/                  # Python、浏览器及专项回归
├── scripts/                # 开发、检查、构建、发布和维护工具
├── assets/                 # 受版本管理的静态资源
├── wiki/                   # VitePress 公开文档源
│   ├── .vitepress/         # 导航、路由重写与阅读主题
│   └── public/             # 文档图示和截图等静态资源
├── docs/                   # 当前工程契约与历史资料索引
├── runtime-image.lock.json # 不可变生产运行环境
├── requirements-runtime.txt
├── requirements-dev.txt
├── Dockerfile
├── docker-compose.yml
├── CONTRIBUTING.md
└── AGENTS.md
```

工具和依赖约束见 `package.json`、`.nvmrc`、`.python-version`、`tsconfig.json`、`pyproject.toml` 及 lint 配置。安装与运行见[本地开发](/development/local-development)。

## 前端职责

| 路径                                                    | 职责                                              |
| ------------------------------------------------------- | ------------------------------------------------- |
| `src/main.tsx`、`src/react/App.tsx`                     | Provider、会话、公开扫码与工作区入口              |
| `src/react/features/`                                   | 按领域组织 View、表单和操作编排；由 shell 懒加载  |
| `src/react/components/`                                 | 跨领域公共组件与 UI 适配                          |
| `src/react/api/`、`src/contracts/`                      | client、Query hooks、查询键和按领域组织的响应类型 |
| `src/react/state/`                                      | 导航、工作区显示与本地 UI 偏好                    |
| `src/domain/`                                           | 可测试的纯业务函数                                |
| `src/react/print/`                                      | 笼卡、二维码、数量统计表和结算模板                |
| `src/theme/`、`src/styles/`                             | 主题唯一源、生成 Token 和按归属划分的样式         |
| `src/react/releaseNotesDocs.ts`、`src/react/version.ts` | 由更新日志或版本脚本同步的派生内容                |

领域覆盖接收、检疫、笼卡／笼位、动物管理、饲养费、技术服务费、单据跟踪、实验人员、反馈和设置。页面名称与目录名不必一一对应，是否现役必须追踪实际 View 和调用链。

`WorkflowCenterView` 当前仅挂载 `BillingWorkflowPanel`。旧应收、报销单、核销中心和历史台账页签等未接入实现登记在 `docs/contracts/frontend-lifecycle.json`，由 `npm run check:frontend-lifecycle` 核对。类型依赖、孤立测试与兼容导出不能证明页面可达；共用工具与后端接口需单独判断。

## 后端职责

| 路径                                        | 职责                                                        |
| ------------------------------------------- | ----------------------------------------------------------- |
| `server.py`、`server_app/legacy.py`         | 启动、装配和历史导出兼容                                    |
| `server_app/web/`                           | Router、HTTP 生命周期、鉴权、解析与响应                     |
| `server_app/domains/`                       | 领域 service、repository、rules 与 importer，新业务在此扩展 |
| `server_app/persistence/`                   | schema 注册、幂等迁移、索引与回填                           |
| `server_app/repositories/`                  | SQL、分页、结构化列和 payload 兼容                          |
| `server_app/services/`                      | 仍参与调用的 service 兼容导出                               |
| `server_app/config.py`、`storage_layout.py` | 环境变量、路径及旧运行目录迁移                              |
| `server_app/cache.py`、`runtime_logging.py` | 短缓存与失效、脱敏日志和请求关联                            |
| `server_app/static.py`、`server_app/pdf/`   | 生产静态资源及服务端 PDF                                    |

结算、权限、流程状态与迁移的改动，需要同时评估前端调用、HTTP、数据库、缓存和审计。完整依赖方向见仓库 `docs/contracts/module-boundaries.md`。

## 运行与生成目录

| 路径                                  | 来源与处理方式                                           |
| ------------------------------------- | -------------------------------------------------------- |
| `web-dist/`                           | 应用及文档生产构建，由 Python 服务读取                   |
| `dist/`                               | 发布与离线交付产物，仅交付任务生成                       |
| `data/`                               | SQLite、附件、索引、日志与缓存；实际路径可由环境变量覆盖 |
| `node_modules/`、`.venv/`             | 依赖安装生成的运行环境                                   |
| `playwright-report/`、`test-results/` | 测试报告及失败证据                                       |

这些目录不作为手工代码修改入口。不能因服务在 localhost 就认定运行数据可丢弃；调试写入使用显式隔离数据。生产路径和备份范围见[部署与运行](/operations/deployment#确认数据实际写在哪里)。

## 文档、契约与生成内容

`wiki/` 面向使用、部署和开发读者，构建到应用 `/docs/`；`docs/contracts/` 维护当前工程约束，入口为仓库 `docs/contracts/README.md`；`docs/archives/` 保留历史基线与证据。`README.md`、`CONTRIBUTING.md`、`AGENTS.md` 分别承担项目入口、贡献流程和代理工作规则。

API 接口清单由 `api-inventory.json` 与生成脚本维护，系统更新记录来自 `wiki/更新日志.md`，不要手工修改派生内容。文档分层和同步规则见 `docs/contracts/documentation-system.md`，常用验证与交付命令分别见[测试与质量](/development/testing-and-quality)和[发布与交付](/development/release-and-delivery)。
