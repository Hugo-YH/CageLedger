# 部署与运行

本页覆盖开发、生产、Docker、群晖 NAS、离线包和升级回滚。

## 运行模型

| 模式     | 前端                                     | API                                | 数据库                                 |
| -------- | ---------------------------------------- | ---------------------------------- | -------------------------------------- |
| 开发     | Vite `5173` 与 VitePress `5175`          | Python `5174`，由 Vite 代理 `/api` | `data/database/cageledger.sqlite`      |
| 本地生产 | Python `5173` 提供 `web-dist/` 和 `/api` | 同一进程                           | `data/database/cageledger.sqlite`      |
| Docker   | 容器 `5173`                              | 同一容器                           | `/app/data/database/cageledger.sqlite` |

## 开发模式

```bash
npm ci
npm run dev
```

- 页面：`http://localhost:5173`
- API：`http://127.0.0.1:5174`
- 文档：`http://127.0.0.1:5175`，通过应用的 `/docs/` 代理访问
- 临时隔离数据库：`CAGELEDGER_EPHEMERAL_DB=1 npm run dev`
- 自定义 API：`CAGELEDGER_API_ORIGIN=http://127.0.0.1:5174 npm run dev`
- 自定义开发端口：`CAGELEDGER_DEV_PORT=5183 CAGELEDGER_DEV_API_PORT=5184 npm run dev`

## 本地生产模式

```bash
npm start
```

`npm start` 先执行 Vite 构建，再启动 Python 服务。构建输出是 `web-dist/`，生产服务在 `5173` 同时提供 SPA、静态资源和 API。

也可以分步执行：

```bash
npm run build
python3 server.py
```

## Docker 镜像

Dockerfile 使用多阶段构建：

1. Node 22 阶段执行 `npm ci` 和 `npm run build`。
2. Python 3.13 阶段安装 `openpyxl`，复制后端和 `web-dist/`。
3. 运行阶段只启动 `python3 server.py`。

正式镜像：

```text
git.cellnucle.us/hugo/cageledger:<tag>
```

## Docker Compose

```bash
mkdir -p /volume1/docker/cageledger
cd /volume1/docker/cageledger
git clone https://git.cellnucle.us/hugo/cageledger.git .
cp .env.example .env
docker compose pull
docker compose up -d
```

访问：`http://NAS地址:5173`。

固定版本：

```bash
CAGELEDGER_IMAGE_TAG=<version> docker compose pull
CAGELEDGER_IMAGE_TAG=<version> docker compose up -d
```

`docker-compose.yml` 使用 Gitea 镜像。`docker-compose.offline.yml` 用于离线源码构建。

## 数据持久化

容器内数据目录：

```text
/app/data
```

群晖 Compose 默认将 Compose 文件同级目录的 `data/` 绑定到容器：

```yaml
volumes:
  - ./data:/app/data
```

若 Compose 文件位于 `/volume1/docker/cageledger/`，宿主机数据目录为 `/volume1/docker/cageledger/data/`。运行目录结构：

```text
data/
├── database/                  # SQLite、WAL、SHM
├── indexes/iacuc/             # 当前 IACUC JSON 索引
├── files/                     # 巡检图片、巡检附件、报销附件
├── cache/pdf/                 # 可清理的 PDF 生成缓存
├── backups/database/          # SQLite 一致性备份
├── inbox/iacuc/               # 后续外部 Excel 投递入口
├── archive/iacuc/             # 后续已导入 Excel 归档
└── failed/iacuc/              # 后续校验失败文件与报告
```

升级到该版本后的首次启动会自动迁移旧的根目录文件，并在 `data/rollback/` 保留一次回退副本；下一次成功启动后自动清理。升级前仍应备份整个 `data/` 目录。

重点备份：

- `database/cageledger.sqlite`
- `database/cageledger.sqlite-wal`
- `database/cageledger.sqlite-shm`
- `indexes/iacuc/index.json`
- `files/`

WAL 和 SHM 是运行时伴随文件，checkpoint 或服务停止后可能消失。备份以 SQLite 一致性为准，详见 [[备份与维护]]。

## 离线源码包

```bash
npm run package:offline
```

输出：

```text
dist/CageLedger-offline-<version>.tar.gz
```

离线包包含 `web-dist/`。目标机器直接运行：

```bash
tar -xzf CageLedger-offline-<version>.tar.gz
cd cageledger
python3 -m pip install -r requirements.txt
python3 server.py
```

运行目标机器无需 Node.js。Excel 历史报销导入依赖 `openpyxl`，服务端 PDF 导出使用 Playwright 驱动的常驻 Chromium 与系统中文字体；Docker 镜像已包含这些运行组件。服务启动时会预热浏览器进程，单份与批量导出复用该进程。已保存统计表会在后台预热单表与对应项目负责人汇总 PDF，导出请求显示进度并在完成后自动下载；缓存文件默认位于 `data/cache/pdf/`。离线源码运行时安装 Chromium，或通过 `CAGELEDGER_CHROMIUM_BIN` 指向 Chromium 可执行文件。

## 离线镜像包

办公室 NAS、离线 Docker 主机和无法直连 Gitea Registry 的环境，使用本地导出的离线镜像包。

```bash
npm run package:offline:image
```

输出：

```text
dist/CageLedger-image-<version>-amd64.tar.gz
dist/CageLedger-image-<version>-arm64.tar.gz
dist/CageLedger-image-<version>-load.txt
dist/CageLedger-image-<version>-sha256.txt
```

镜像 tag 只带版本号，例如 `1.0.0-beta21`；`build` 为纯数字构建号，仅用于系统内版本展示，不进入软件包 tag。

加载示例：

```bash
docker load -i CageLedger-image-<version>-amd64.tar.gz
docker tag git.cellnucle.us/hugo/cageledger:<version>-amd64 \
  git.cellnucle.us/hugo/cageledger:<version>
docker run -d --name cageledger -p 5173:5173 \
  -v /volume1/docker/cageledger/data:/app/data \
  git.cellnucle.us/hugo/cageledger:<version>
```

ARM64 主机将文件名替换为 `-arm64.tar.gz` 即可。

## 升级

升级前备份 SQLite、`.env` 和 Compose 文件。

```bash
git pull --ff-only origin main
CAGELEDGER_IMAGE_TAG=<new-version> docker compose pull
CAGELEDGER_IMAGE_TAG=<new-version> docker compose up -d
```

服务启动时自动执行幂等 SQLite schema 初始化、字段补齐、索引创建和必要数据回填。旧数据库无需人工 SQL 操作。

升级后检查：

```bash
curl http://127.0.0.1:5173/api/health
docker logs --tail 200 cageledger
```

再验证管理员登录、房间管理员权限、笼卡、笼位、统计表、结算和流程中心。

## 回滚

1. 停止写入并备份当前数据库。
2. 固定上一版镜像 tag。
3. 启动上一版容器并挂载原数据目录。
4. 检查 `/api/health` 和关键业务链。

新增字段和索引通常支持旧版本忽略。涉及删除字段、重写数据或不可逆迁移的版本需要同时恢复升级前数据库备份，发布说明应明确标注。

## 群晖建议

- 项目目录固定为 `/volume1/docker/cageledger`。
- 数据使用 `/volume1/docker/cageledger/data` bind mount，便于备份和迁移。
- 使用 Hyper Backup 或 Btrfs Snapshot 管理数据目录。
- 外部访问通过受控反向代理和 HTTPS。
- 内网自签名证书的下载、校验和客户端安装见 [HTTPS 与证书](/operations/https-and-certificate)。
- 升级使用明确版本 tag，避免长期跟随 `latest`。
