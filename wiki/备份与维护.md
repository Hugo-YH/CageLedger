# 备份与维护

本页说明数据目录、备份频率和恢复关注点。

## 必备备份项

- SQLite 数据库目录
- `data/logs/`：运行日志及轮转文件，升级前与数据目录一起归档，避免轮转后失去故障线索。
- `data/files/`（包括 `quarantine/` 下的原始资料及所有版本Word报告）
- `data/files/feedback/` 与 SQLite 内的 `feedback*` 表：原始反馈、补充、截图、遇到记录、工单关联及同步任务必须一起恢复。
- `.env` 或部署环境变量
- `docker-compose.yml`
- 导出的结算文件

推荐直接备份整个部署目录和 `./data` 挂载目录。

## 建议频率

| 频率       | 内容                          |
| ---------- | ----------------------------- |
| 每日       | SQLite 数据库和 `data/files/` |
| 每周       | 部署目录和配置                |
| 每次升级前 | 数据库、Compose、环境变量     |
| 每次结算后 | 导出的结算文件                |

## 群晖建议

- 使用 Hyper Backup
- 配合 Btrfs Snapshot
- 定期演练恢复

## 恢复关注点

- 数据库文件与 WAL 伴随文件保持同目录
- 检疫记录与 `files/quarantine/` 同批备份和恢复；仅恢复SQLite不能找回附件与Word。停服后复制整个数据目录，或使用覆盖整个目录的一致性快照。恢复后抽查旧版Word与原始附件下载。
- 反馈恢复后抽查原始截图、补充、工单编号和遇到人数。保留原请求标识、目标仓库身份及同步任务；服务重启会恢复未完成任务，结果不确定的建单先核对远端标识，禁止清空关联后重新建单。
- 环境变量与数据库一起恢复，避免管理员账号或更新检查配置漂移
- 恢复后先检查 `IACUC` 回填、登录和首页数据是否正常
- 版本回滚优先切换上一版镜像 tag，并保留当前数据库副本；涉及破坏性迁移时恢复升级前备份

## 日常维护建议

- 升级前先备份
- 定期检查磁盘空间
- 定期导出关键月份结算单
- 变更配置后记录当前版本和部署时间

## 查看运行日志

在部署目录执行：

```bash
tail -n 100 data/logs/runtime.jsonl
docker logs --timestamps --tail 100 cageledger
```

正常运行使用 `data/logs/runtime.jsonl` 排查；`docker logs` 主要查看启动提示和文件写入失败后的降级日志。两者不会正常保存两份完整运行日志。
持久化日志逐行保存 JSON，包含 UTC 时间、版本、线程、请求 ID、结果与脱敏异常位置。轮转文件为 `runtime.jsonl.1` 至 `runtime.jsonl.4`，数字越大越旧；默认按容量保留，不保证固定天数。
排查锁错误时查找 `database_lock_error`，通过请求 ID、线程、操作类型和调用位置核对相关请求或后台任务。
IACUC 导入、反馈同步、PDF/Word 导出、文件处理、AI 和启动失败也有对应事件。重复错误一分钟限频，后续同类日志的 `suppressedCount` 表示期间额外发生的次数。
未捕获异常会保存类型和代码位置；日志不包含原始异常消息、SQL 参数、附件内容和外部服务令牌。

删除或重建容器不会删除挂载目录中的日志。日志目录写入失败时，控制台出现 `runtime_log_unavailable`；检查空间和权限，修复后重启服务恢复文件记录。
SQLite 单文件备份不包含运行日志，需单独备份 `data/logs/` 或整个部署目录。浏览器诊断仍通过现有反馈摘要收集；Docker 宿主机、NAS 和外部服务日志由各自部署维护。
