# 开发维护

本区域面向开发者、测试与交付维护者，提供从当前实现、环境启动到代码修改和版本交付的阅读路径。先确认现役入口与兼容边界，再按改动读取架构和契约，最后用与风险匹配的验证交付结果。

## 第一次接手项目

| 顺序 | 阅读入口                                            | 解决的问题                                     |
| ---- | --------------------------------------------------- | ---------------------------------------------- |
| 1    | [当前版本与兼容边界](/development/current-baseline) | 当前页面在哪里，哪些实现仅保留兼容             |
| 2    | [本地开发](/development/local-development)          | 安装运行时，使用隔离数据启动应用、API 与文档   |
| 3    | [项目结构](/development/project-structure)          | 入口、领域、生成目录与文档分别由谁负责         |
| 4    | [开发规范](/development/contributing)               | 分支、状态、写入、UI、数据与交付应遵守哪些边界 |

仓库 `CONTRIBUTING.md` 提供贡献流程，`AGENTS.md` 约束代理工作。当前工程契约按任务汇总在仓库 `docs/contracts/README.md`，不需要为一次局部修改通读所有契约。

## 建立一次可复核的修改

1. 对齐当前分支、远端和已有改动，追踪真实生产入口。
2. 在现有领域边界实现，保留业务语义、兼容字段和授权规则。
3. 同步对应指南或契约，按 diff 选择目标测试，检查格式、链接和最终差异。
4. 报告实际验证结果与限制；日常提交推送和正式制品发布分别执行。

`release:cloud` 只核验已经备好的标签、产物与 Packages 后发表 Release，不自动改版本、测试、构建或推送。具体交付顺序见[发布与交付](/development/release-and-delivery)，生产运行与恢复见[部署与运维](/operations/)。

历史方案与验收在 `docs/archives/`，原 `docs/plan/`、`docs/progress/` 等路径保留兼容索引。历史记录用于追溯当时决策，不替代当前源码、现行契约或本次授权。
