# 文档图文与引用

本页面向文档维护者，说明界面截图、原创图示、设计依据和外部引用的维护方法。内容组织、事实来源及历史归档规则统一见仓库 `docs/contracts/documentation-system.md`。

## 阅读与视觉约定

文档按使用、运维和开发三条路径组织，每条路径有独立导航页；单页先交代任务与入口，再写操作、核对结果和异常处理。已有公开地址保持稳定，新增页面登记路由、侧栏和 `LLMs.md`。

文档站采用 VitePress，读取项目从 `src/theme/visual-system.mjs` 生成的品牌 Token。颜色、圆角、间距、焦点与深浅主题遵循项目 Ant Design 设计契约；长文保留适合阅读的字号、行距与内容宽度。Ant Design 的导航、排版与设计 Token 原则作为设计依据<sup>[1](#参考资料)</sup><sup>[2](#参考资料)</sup><sup>[3](#参考资料)</sup>，站点导航与搜索复用 VitePress 现有能力<sup>[4](#参考资料)</sup>。

| 内容       | 展示方式                         | 维护要求                         |
| ---------- | -------------------------------- | -------------------------------- |
| 操作步骤   | 有序列表，使用实际菜单和按钮名称 | 说明完成后的核对位置             |
| 规则与差异 | 短段落或对照表                   | 长表格在容器内横向滚动           |

| 外部依据   | 就近脚注、原始链接与访问日期     | 区分引用、改绘和转载             |

### 更新截图

1. 通过受管入口运行 `npm run test:e2e -- tests/e2e/documentation-capture.spec.ts`。
2. 检查证据目录中的原图，确认页面已加载、关键操作可见且没有真实人员、经费、合格证或生产数据。
3. 使用该次运行的 `capture-manifest.json` 与 `chromium/results.json` 执行发布脚本：

```bash
node scripts/documentation/publish-screenshots.mjs <capture-manifest.json> <results.json>
```

脚本核对版本、成功报告、同一证据目录、图片清单、尺寸与摘要后才复制到文档目录。普通测试运行只产生证据，不覆盖已发布图片。相关界面发生变化时，同时更新截图、图注和替代文本。

## 原创流程图与逻辑图

`wiki/public/diagrams/` 下八张 SVG 为本项目原创，用于业务全景、检疫、计费、单据阶段、系统结构、请求链、备份恢复和发布交付。可通过以下命令从源定义重新生成：

```bash
node scripts/documentation/generate-diagrams.mjs
```

源文件位于 `scripts/documentation/generate-diagrams.mjs`。图使用文字和箭头表达关系，每张图具有独立标题、描述及正文图注；点击可查看原始尺寸。阶段图中的锁定、解锁与撤回是独立操作，不能按节点编号推断未注明的状态迁移。

图片统一通过 `DocFigure` 展示，提供替代文本、说明、原图入口与延迟加载。深色模式保留截图和图示的原始浅色画布，周围文字与边框随主题变化，避免改色造成状态误读。
